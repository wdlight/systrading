## 1. 작업 목표

실거래까지 9시간 남은 시점에서, `docs/impl/1012.sale.bugfix.md` 리뷰를 통해 발견된 다수의 치명적인 런타임 오류를 해결하고, 시스템이 최소한의 안정성을 확보하여 실제 매매를 수행할 수 있도록 하는 것을 목표로 한다.

## 2. 1차 수정 내역 (계획 기반)

- **`korea_invest.py`**: `buy/sell/modify/cancel/inquire` 메서드 추가 및 `APIResponse` 반환 로직 적용.
- **`order_service.py`**: 인메모리 캐시를 제거하고 `korea_invest.py`를 호출하도록 전면 리팩토링.
- **`trview/page.tsx`**: 하드코딩된 잔고 정보를 실제 API(`/api/account/balance`) 호출을 통해 받아오도록 수정.
- **`useOrders.ts`**: 불필요한 `order_side` 파라미터 제거.
- **`test_order_service.py`**: 기본 단위 테스트 케이스 추가.

## 3. 2차 긴급 수정 내역 (리뷰 피드백 반영)

1차 수정 완료 후 코드 리뷰에서, 실제 `ki_api.py`의 구현과 불일치하는 부분과 잘못된 객체 사용으로 인한 다수의 `AttributeError`, `ValidationError`가 발견되었다. 아래와 같이 긴급 수정을 진행했다.

### 3.1. `order_models.py` 수정

- **`OrderDetail` 모델 확장**: 주문 정정/취소에 필수적인 `branch_code` (`ord_gno_brno`), `org_order_no` (`orgn_odno`) 필드를 추가했다.
- **파싱 편의성 개선**: Pydantic의 `alias` 기능을 사용하여 API 응답 컬럼명이 모델 필드에 자동으로 매핑되도록 설정했다.

### 3.2. `korea_invest.py` 수정

- **API 호출 메서드 수정**: `ki_api.py`의 실제 메서드 시그니처와 일치하도록 `KoreaInvestAPIService`의 메서드들을 수정했다.
  - `inquire_pending_orders`: `get_daily_ccld`를 `CCLD_DVSN="02"`(미체결) 조건으로 호출하도록 변경.
  - `inquire_order_history`: `get_daily_ccld`를 `CCLD_DVSN="01"`(체결) 조건으로 호출하도록 변경.
  - `modify_order`, `cancel_order`: `revise_order`, `cancel_order`를 호출하도록 하고, 파라미터를 `org_branch_code`, `org_order_no` 등으로 통일했다.

### 3.3. `order_service.py` 전면 재수정

- **`DataFrame` 파싱 로직 구현**: `get_daily_ccld`가 반환하는 `DataFrame`을 입력받아 `OrderDetail` 리스트로 변환하는 `_parse_order_df` 헬퍼 함수를 구현했다. 이 과정에서 `NaN` 값을 `None`으로 변환하고, `datetime` 파싱, `order_side` 계산 등 모든 데이터 가공을 처리한다.
- **`OrderDetail` 생성 로직 수정**: `OrderDetail.parse_obj(item)`을 사용하여 `alias` 기반으로 안전하게 모델을 생성하도록 변경, `ValidationError`를 원천 차단했다.
- **주문 정정/취소 기능 구현**: 임시 비활성화했던 `modify_order`, `cancel_order`를 **재구현**했다. 이제 미체결 내역을 먼저 조회하여 `branch_code`, `org_order_no`를 확보한 뒤, 이를 이용해 실제 정정/취소 API를 호출하는 안정적인 방식으로 동작한다.
- **API 응답 처리 수정**: `place_buy_order` 등에서 `APIResponse` 객체의 `msg1`, `output` 속성을 `getattr`로 안전하게 접근하여 `AttributeError`를 해결했다.

### 3.4. `test_order_service.py` 수정

- `OrderRequest` 생성 시 누락되었던 `stock_name` 필드를 추가하여 테스트가 정상 실행되도록 수정했다.

## 4. 최종 결과

- **동작 상태**: 매수, 매도, 미체결/체결 조회, **주문 정정 및 취소** 기능이 모두 백엔드에서 정상적으로 구현되었으며, 실제 API 명세와 일치하도록 수정되었다.
- **안정성**: 런타임에 발생할 수 있었던 다수의 `AttributeError`와 `ValidationError`가 해결되어 시스템 안정성이 크게 향상되었다.
- **후속 조치**: 프론트엔드의 `OrderModifyRequest`, `OrderCancelRequest` 모델이 백엔드가 요구하는 필드(`order_number`, `stock_code`, `quantity`, `price`)를 정확히 보내고 있는지 최종 확인 후, 샌드박스 환경에서의 통합 테스트가 필요하다.
