## 🔬 근본 원인 분석

### 문제의 연쇄 과정

1. **기존 Next.js 프로세스 문제**
   - 원인: 장시간 실행으로 인한 메모리 누수 또는 상태 손상 가능
   - 증상: 500 Internal Server Error

2. **.next 빌드 캐시 손상**
   - 원인:
     - 개발 중 핫 리로드 반복으로 인한 캐시 불일치
     - 종속성 업데이트 후 캐시 미갱신
   - 증상: ChunkLoadError - 청크 파일 로드 타임아웃

3. **React 컴포넌트 초기화 실패**
   - 원인: 청크 로드 실패로 인한 앱 레이아웃 렌더링 불가
   - 증상: useEffect 훅 실행 불가 → API 호출 없음 → 데이터 미표시

### 해결 핵심
- `.next` 캐시 삭제로 클린 빌드 강제
- 컴파일된 청크 파일 재생성
- React 앱 정상 초기화 → 훅 실행 → API 호출 → 데이터 로딩

## 🔄 추가 작업: 일봉 캐시 증분 갱신 보강 (13:40 - 14:05)

**배경**
- 10월 10일 데이터가 일봉 차트에서 누락되는 사례 재현.
- `ChartCacheService.get_daily_candles()`가 연 단위 풀스캔을 반복하면서도 응답이 비거나 실패하면 기존 캐시를 덮어쓰는 문제가 있어 데이터가 사라질 수 있음.
- KIS API 호출 범위가 과도해 응답 지연 및 실패 확률이 올라가던 상황.

**수정 사항**
- `backend/app/services/chart_cache_service.py`
  - 요청 구간과 당일 기준으로 연도별 조회 범위를 제한하고, 최초 로드도 해당 구간만 호출.
  - 현재 연도 캐시에 대해서는 마지막 일자 기준 3일 이상 공백이 있고 요청 범위 내에 더 최신 거래일이 있을 때만 보충 조회.
  - 거래일 캘린더와 캐시 일자를 비교해 누락 일자를 추적하고, 필요한 최소 범위만 재조회.
  - `_merge_daily_candles` / `_get_candle_date` 보조 함수로 기존·신규 데이터를 날짜 키 기반으로 병합해 덮어쓰기 문제 방지.

**검증**
```bash
python3 -m py_compile backend/app/services/chart_cache_service.py
```
- 캐시 삭제 후 2024-10-09~2024-10-11 범위를 요청해 API 호출 범위가 3일로 제한되는지 로그로 확인.
- 기존 캐시가 있을 때는 누락 일자만 재조회하는지 수동 테스트.

**추가 권장 사항**
1. 실 계좌/샌드박스 환경에서 2024-10-10과 같이 빈 구간이 있는 종목을 대상으로 `get_daily_candles` 호출해 데이터 보강 여부 확인.
2. `kordata/<종목>/daily/*.json` 재작성 주기를 모니터링해 불필요한 I/O가 발생하지 않는지 점검.
3. 주/월봉 데이터에도 동일한 증분 로직을 적용하거나 공용 유틸로 추상화하는 작업 검토.
