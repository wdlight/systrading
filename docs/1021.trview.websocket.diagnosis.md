# TRView 페이지 실시간 분봉 업데이트 진단 보고서

**문서 ID**: `1021.trview.websocket.diagnosis.md`
**작성일**: 2025-10-21
**진단 도구**: Chrome DevTools MCP
**상태**: 🔴 **WebSocket 연결 실패 - 근본 원인 파악 완료**

---

## 📋 Executive Summary

### 진단 결과

`/trview` 페이지에서 **WebSocket 연결이 전혀 이루어지지 않아** 실시간 분봉 업데이트가 불가능한 상태입니다.

### 핵심 발견사항

- ❌ **WebSocket 연결 시도 자체가 없음** (네트워크 요청 0건)
- ❌ `wsManager` 전역 객체가 브라우저에 노출되지 않음
- ✅ 백엔드 WebSocket 서버는 정상 작동 중 (`/ws` 엔드포인트 존재)
- ✅ `useWebSocket()` 훅은 코드상 정상적으로 호출됨
- ✅ REST API 호출은 모두 정상 작동

### 원인 추정

**Next.js 클라이언트 사이드 렌더링 문제** 또는 **useWebSocket 훅 초기화 실패**로 추정됩니다.

## 🎯 근본 원인 분석

### 가설 1: useWebSocket 훅이 실행되지 않음 ⭐️ **최유력**

**증거**:

1. `console.log('🚀 WebSocket 연결 시도 시작')` 로그가 콘솔에 없음
2. `wsManager` 전역 객체가 브라우저에서 `undefined`
3. WebSocket 네트워크 요청 0건

**가능한 원인**:

- ❌ Next.js SSR/CSR 하이드레이션 오류로 useEffect가 실행되지 않음
- ❌ `/trview/page.tsx` 컴포넌트가 실제로 마운트되지 않음
- ❌ 다른 JavaScript 에러로 인해 useEffect 실행 전 컴포넌트 크래시

**검증 방법**:

- 브라우저 콘솔에서 JavaScript 에러 확인
- React DevTools로 컴포넌트 트리 확인
- `console.log` 추가하여 컴포넌트 렌더링 여부 확인

---

### 가설 2: 콘솔 로그가 너무 많아 묻힘

**증거**:

- `list_console_messages` 호출 시 92,000+ 토큰 (엄청난 양의 로그)

**가능한 원인**:

- 다른 컴포넌트에서 과도한 로그 출력
- WebSocket 로그가 쏟아지는 로그 사이에 묻힘

**검증 방법**:

- 콘솔 clear 후 재로드
- 특정 키워드("WebSocket", "🚀") 필터링

---

### 가설 3: 잘못된 페이지를 보고 있음

**증거**:

- URL은 `http://localhost:9000/trview`가 맞음
- 하지만 `#__next` div가 없음 (비정상적인 Next.js 구조)

**가능한 원인**:

- `/trview` 경로가 다른 라우팅 시스템에 의해 오버라이드됨
- 실제로는 다른 페이지가 렌더링되고 있음

**검증 방법**:

- 페이지 소스 보기
- React DevTools로 컴포넌트 트리 확인
