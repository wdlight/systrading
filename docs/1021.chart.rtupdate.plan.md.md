
# 실시간 분봉 차트 업데이트 문제 해결 계획

**문서 ID**: `1021.chart.rtupdate.plan.md`  
**작성일**: 2025-10-21  
**작성자**: Gemini Code Assist  
**상태**: **계획 수립 완료**

---

## 1. 문제 정의 (Problem Definition)

현재 시스템에서 실시간 호가창(`OrderBook.tsx`)은 약 1초 주기로 정상 업데이트되지만, 분봉 차트는 1분이 지나도 새로운 분봉이 생성되거나 렌더링되지 않는 문제가 발생하고 있다. 이로 인해 사용자는 실시간 시세 흐름을 차트를 통해 파악할 수 없다.

**목표**: 최소한의 코드를 변경하여 문제의 원인을 진단하고, 실시간으로 새로운 분봉이 차트에 그려지도록 시스템을 수정한다.

---

## 2. 원인 분석 (Root Cause Analysis)

`docs/plan/mincandle/` 하위 문서들과 프론트엔드/백엔드 아키텍처를 종합적으로 검토한 결과, 문제의 핵심 원인은 **백엔드에서 생성된 '완성된 분봉' 데이터가 프론트엔드 차트에 전달 및 반영되지 않기 때문**이다.

### 2.1. 백엔드: 분봉 캐시 자동 저장 기능 비활성화

- **현상**: 백엔드 `realtime_service.py`는 1분 단위로 '완성된 분봉'을 생성하지만, 이를 파일 캐시(`kordata/*.json`)에 저장하는 핸들러(`_minute_persist_handler`)가 연결되어 있지 않다 (`None` 상태).
- **결과**: 캐시 파일은 REST API(`api/chart/...`)를 호출해야만 갱신된다. WebSocket 스트림만으로는 캐시가 업데이트되지 않아 데이터 불일치가 발생한다.

### 2.2. 프론트엔드: '완성된 분봉' 이벤트 미구독

- **현상**: 백엔드는 1분이 경과하여 분봉이 완성되면 `minute_candle_finalize` 이벤트를 WebSocket으로 브로드캐스트한다. 하지만 현재 프론트엔드의 차트 훅(`useRealtimeMinuteCandles.ts` 추정)은 실시간으로 변하는 '진행중인 분봉'(`minute_candle_update`) 이벤트만 구독하고 있다.
- **결과**: 1분이 지나 새로운 분이 시작되어도, '완성된 분봉'을 받아 기존 차트 데이터에 병합하는 로직이 없어 차트가 업데이트되지 않는다.

### 2.3. 잘못된 가정 수정

> **가정**: "프론트엔드에서 받은 호가 데이터로 신규 분봉을 만들어 렌더링해야 한다."

> **분석**: 이는 현재 아키텍처와 다르다. 호가 데이터(매수/매도 대기 물량)와 분봉 차트(실제 체결 데이터)는 별개의 스트림이다. 분봉 생성의 책임은 전적으로 **백엔드**에 있으며, 프론트엔드는 백엔드가 생성한 분봉 데이터를 받아서 그리기만 하면 된다.

## 3. 해결 계획 (Solution Plan)

문제의 원인을 빠르게 진단하고 최소한의 변경으로 해결하기 위해 다음 3단계 계획을 제안한다.

### 3.1. 1단계: 프론트엔드에서 `minute_candle_finalize` 이벤트 수신 확인 (진단)

가장 먼저 백엔드가 '완성된 분봉' 이벤트를 정상적으로 보내고 있는지 프론트엔드에서 직접 확인하여 문제의 원인이 백엔드인지 프론트엔드인지 즉시 가려낸다.

1.  **실행**: 분봉 차트가 표시된 페이지에서 Chrome 개발자 도구의 Console을 연다.
2.  **코드 주입**: 아래 스크립트를 콘솔에 붙여넣고 실행하여 모든 WebSocket 수신 메시지를 로깅한다.

    ```javascript
    if (window.wsListenerAttached) {
      console.log("이미 WebSocket 리스너가 연결되어 있습니다.");
    } else {
      const originalSend = WebSocket.prototype.send;
      WebSocket.prototype.send = function(data) {
        originalSend.apply(this, arguments);
      };
    
      const originalOnMessage = WebSocket.prototype.onmessage;
      WebSocket.prototype.onmessage = function(event) {
        const data = JSON.parse(event.data);
        // 모든 메시지 타입을 콘솔에 출력
        console.log('📬 WS 수신:', data);
    
        if (data.type === 'minute_candle_finalize') {
          console.log('🎉🎉🎉 [발견!] 완성된 분봉 데이터 수신:', data);
        }
        if (originalOnMessage) {
          return originalOnMessage.apply(this, arguments);
        }
      };
      window.wsListenerAttached = true;
      console.log("WebSocket 메시지 리스너가 연결되었습니다. 1~2분 정도 기다려보세요.");
    }
    ```

3.  **관찰**: 1~2분간 대기하며 콘솔 로그를 확인한다.

    -   **`🎉🎉🎉 [발견!]` 로그가 보일 경우**:
        -   **원인**: 백엔드는 정상. 프론트엔드에 구독 및 처리 로직이 누락된 것.
        -   **조치**: **3.2. 2단계**로 진행한다.

    -   **`minute_candle_finalize` 로그가 보이지 않을 경우**:
        -   **원인**: 백엔드가 이벤트를 브로드캐스트하지 않거나, 분봉 집계 자체에 문제가 있는 것.
        -   **조치**: 백엔드 `realtime_service.py`의 `_flush_closed_candle` 함수 주변의 로그를 확인하여 브로드캐스트 로직이 정상 실행되는지 점검한다.

### 3.2. 2단계: 프론트엔드 차트 훅 수정 (구현)

1단계에서 `finalize` 이벤트 수신이 확인되면, `docs/plan/mincandle/1019.update.impl.md` 문서의 "Phase 2" 계획에 따라 프론트엔드 코드를 수정한다.

-   **대상 파일**: `stock-trading-ui/src/hooks/useRealtimeMinuteCandles.ts`
-   **수정 내용**:
    1.  `subscribeToMinuteCandleFinalize` 헬퍼를 사용하여 `minute_candle_finalize` 이벤트를 구독한다.
    2.  수신된 '완성된 분봉' 데이터를 별도의 `finalizedCandles` 상태 배열에 저장한다.
    3.  차트 컴포넌트(`RealtimeCandlestickChart.tsx`)에서 기존 차트 데이터(`baseChartData`), '완성된 분봉'(`finalizedCandles`), '진행중인 분봉'(`currentCandle`)을 모두 병합하여 최종 차트 데이터를 생성하는 로직을 구현한다.

### 3.3. 3단계: 백엔드 Persistence Handler 연결 (장기적 안정화)

실시간 차트 문제는 2단계까지만으로도 해결되지만, 데이터 일관성을 유지하고 불필요한 API 호출(Gap-filling)을 방지하기 위해 백엔드에서 완성된 분봉을 캐시 파일에 저장해야 한다.

-   **대상 파일**: `backend/app/main.py`
-   **수정 내용**:
    1.  `docs/plan/mincandle/1019.update.impl.md` 문서의 "Phase 1" 계획에 따라, `TradingService.update_minute_candle`을 호출하는 콜백 함수를 정의한다.
    2.  FastAPI 앱 시작 시, `realtime_service.set_minute_persist_handler()`를 통해 해당 콜백 함수를 주입한다.

## 4. 검증 방안

1.  **실시간 업데이트 검증**:
    -   분봉 차트 페이지에서 1분 경계가 지날 때, REST API 호출 없이(Network 탭 확인) 새로운 분봉이 차트에 추가되는지 확인한다.
    -   동시에 '진행중인 분봉'이 다음 분으로 넘어가 정상적으로 업데이트되는지 확인한다.

2.  **데이터 정합성 검증**:
    -   다른 종목으로 변경했다가 5분 뒤 다시 돌아왔을 때, 5분간의 데이터가 누락 없이 차트에 표시되는지 확인한다.
    -   이때 백엔드 로그에서 Gap-filling 로직이 최소한으로 동작하거나 동작하지 않는 것을 확인하여, WebSocket 기반 캐시 저장이 정상 작동함을 검증한다.
