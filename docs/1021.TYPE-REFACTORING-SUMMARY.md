## 🔧 수정 파일

### 1. `stock-trading-ui/src/lib/types.ts`

**Lines 147-255: 타입 시스템 재설계**

#### Before (기존 구조)

```typescript
// 단일 RealtimeMessage 인터페이스
export interface RealtimeMessage {
  type: 'account_update' | 'minute_candle_update' | ... ;
  timestamp: string;
  data: any;  // ❌ 모든 메시지가 data 필드를 가진다고 가정
}
```

**문제점**:

- `MinuteCandleUpdateMessage`는 `candle` 필드 사용
- 다른 메시지는 `data` 필드 사용
- TypeScript가 이 차이를 감지하지 못함
- Runtime Error 발생 가능

#### After (리팩토링 후)

```typescript
// 1. 베이스 타입 정의
type TimestampedMessage<TType extends string> = {
  type: TType;
  timestamp?: string;
};

// 2. 개별 메시지 인터페이스 정의
export interface MinuteCandleUpdateMessage extends TimestampedMessage<'minute_candle_update'> {
  stock_code: string;
  candle: MinuteCandlePayload;  // ✅ candle 필드
  is_final: boolean;
}

export interface MinuteCandleFinalizedMessage extends TimestampedMessage<'minute_candle_finalized'> {
  stock_code: string;
  candle: MinuteCandlePayload;  // ✅ candle 필드
}

export interface OrderBookUpdate extends TimestampedMessage<'orderbook_update'> {
  stock_code: string;
  data: {  // ✅ data 필드
    asks: OrderBookRow[];
    bids: OrderBookRow[];
    current_price?: number;
    timestamp: string;
  };
}

export interface AccountUpdate extends TimestampedMessage<'account_update'> {
  data: AccountBalance;  // ✅ data 필드
}

// ... 기타 메시지 타입들

// 3. 유니온 타입으로 재정의
export type RealtimeMessage =
  | MinuteCandleUpdateMessage
  | MinuteCandleFinalizedMessage
  | OrderBookUpdate
  | MarketStatusUpdate
  | MarketIndexUpdate
  | AccountUpdate
  | WatchlistUpdate
  | PriceUpdate
  | TradingStatusUpdate
  | OrderUpdate
  | ConnectionStatus
  | HeartbeatMessage
  | PongMessage;
```

```typescript
// ❌ Before: 모든 메시지에 data 필드가 있다고 가정
private handleMessage(message: RealtimeMessage): void {
  const { type, data } = message;  // ❌ TypeScript 오류!

  switch (type) {
    case WS_MESSAGE_TYPES.MINUTE_CANDLE_UPDATE:
      this.notifyListeners(type, message as any);  // ❌ as any 사용
      console.log('...', { type, data });  // ❌ data는 undefined
      break;
    // ...
  }
}

// ✅ After: 타입별로 명시적 캐스팅
private handleMessage(message: RealtimeMessage): void {
  const { type } = message;  // ✅ type만 추출

  switch (type) {
    case WS_MESSAGE_TYPES.CONNECTION_STATUS:
      this.handleConnectionStatus((message as ConnectionStatus).data);
      break;
    case WS_MESSAGE_TYPES.ACCOUNT_UPDATE:
      this.notifyListeners(type, (message as AccountUpdate).data);
      break;
    case WS_MESSAGE_TYPES.MINUTE_CANDLE_UPDATE:
      // ✅ 전체 메시지 객체 전달 (candle 필드 포함)
      this.notifyListeners(type, message as MinuteCandleUpdateMessage);
      console.log('...', { type, candle: (message as MinuteCandleUpdateMessage).candle });
      break;
    case WS_MESSAGE_TYPES.MINUTE_CANDLE_FINALIZED:
      // ✅ 전체 메시지 객체 전달 (candle 필드 포함)
      this.notifyListeners(type, message as MinuteCandleFinalizedMessage);
      console.log('...', { type, candle: (message as MinuteCandleFinalizedMessage).candle });
      break;
    case 'orderbook_update':
      this.notifyListeners(type, (message as OrderBookUpdate).data);
      break;
    // ... 기타 케이스
  }
}
```

## ✅ 해결된 문제

### 1. TypeScript 컴파일 오류 해결

**Before**:

```
websocket.ts:263:19 - error TS2339: Property 'data' does not exist on type 'MinuteCandleFinalizedMessage'.
websocket.ts:263:19 - error TS2339: Property 'data' does not exist on type 'MinuteCandleUpdateMessage'.
websocket.ts:263:19 - error TS2339: Property 'data' does not exist on type 'RealtimeMessage'.
```

**After**:
✅ 모든 분봉 관련 TypeScript 오류 해결됨

### 2. Runtime Error 방지

**Before**:

- `message.data.timestamp` 접근 시 `Cannot read properties of undefined` 오류 발생 가능
- `as any` 캐스팅으로 타입 체크 우회

**After**:

- `message.candle.timestamp` 명시적 접근
- 타입 안전성 확보로 Runtime Error 방지

### 3. 코드 가독성 향상

**Before**:

- 어떤 메시지가 `data` 필드를 가지는지 불명확
- `as any` 캐스팅으로 인한 타입 정보 손실

**After**:

- 각 메시지 타입의 구조가 명확
- IDE 자동완성 지원
- 컴파일러가 타입 오류 감지
