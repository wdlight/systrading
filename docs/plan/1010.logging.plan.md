# 백엔드 로깅 시스템 개선 실행 계획 (2025-10-10)

## 1. 개요
본 문서는 `백엔드 로깅 개선 계획`에 기술된 목표를 달성하기 위한 구체적인 실행 단계와 각 단계에서 수정이 필요한 파일 목록을 정의합니다. `loguru`를 중심으로 표준 로깅(`stdlib logging`)을 통합하고, 설정을 외부화하여 유연하고 강력한 로깅 시스템을 구축합니다.

---

## 2. 실행 계획 (Phases)

### Phase 1: 환경 설정 및 의존성 추가
**목표**: 로깅 설정을 외부에서 제어하기 위한 환경 변수를 추가하고, JSON 로깅에 필요한 라이브러리를 설치합니다.

**수정 및 추가 필요한 파일:**
*   `backend/requirements.txt`
    *   `python-json-logger` (또는 `loguru`의 `serialize=True`를 사용하므로 필수 아님, `loguru`로 통일)
    *   `loguru`가 명시되어 있지 않다면 추가합니다.
*   `backend/.env.example` (및 로컬 `backend/.env`)
    *   `LOG_LEVEL=INFO`
    *   `LOG_FORMAT=console` (개발용 기본값, `json`으로 변경 가능)
*   `backend/app/core/config.py`
    *   `Settings` 클래스에 `LOG_LEVEL: str`과 `LOG_FORMAT: str` 필드를 추가합니다.

### Phase 2: 중앙 로깅 설정 모듈 구현
**목표**: `loguru`를 설정하고 표준 로거의 출력을 가로채는 중앙 설정 모듈(`logging_config.py`)을 구현합니다. 기존 `utils/logger.py`는 이 파일로 대체됩니다.

**수정 및 추가 필요한 파일:**
*   `backend/app/core/logging_config.py` (신규 생성)
    *   `setup_logging` 함수를 정의합니다.
    *   `config.py`의 `Settings`를 참조하여 로그 레벨과 포맷을 동적으로 설정합니다.
    *   `InterceptHandler`를 구현하여 `stdlib logging` 출력을 `loguru`로 리디렉션합니다.
    *   콘솔 핸들러와 파일 핸들러(`TimedRotatingFileHandler` 역할)를 `logger.add()`로 추가합니다.
*   `utils/logger.py` (삭제 대상)
    *   Phase 2 완료 후 삭제됩니다.

### Phase 3: FastAPI 앱에 로거 적용 및 초기화
**목표**: FastAPI 애플리케이션이 시작될 때 중앙 로깅 설정이 적용되도록 하고, 기존의 불필요한 로깅 설정을 제거합니다.

**수정 및 추가 필요한 파일:**
*   `backend/app/main.py`
    *   파일 상단에서 `from app.core.logging_config import setup_logging`을 추가합니다.
    *   `setup_logging()` 함수를 FastAPI 앱 생성 직후 호출합니다.
    *   기존 `logging.basicConfig()` 및 `print()` 구문을 제거합니다.
*   `backend/app/core/korea_invest.py`
    *   `logging.basicConfig()` 호출을 제거합니다.
*   `backend/test_account_integration.py` (및 다른 테스트 파일)
    *   `logging.basicConfig()` 호출을 제거합니다.

### Phase 4: 백엔드 전체 모듈의 로거 교체
**목표**: 백엔드 프로젝트 전체에서 사용되는 로거를 `loguru`로 통일하여 일관성을 확보합니다.

**수정 및 추가 필요한 파일:**
*   **대상**: `backend/app/` 디렉토리 하위의 모든 `.py` 파일 (api, services, websocket, core 등)
    *   `backend/app/api/account.py`
    *   `backend/app/api/trading.py`
    *   `backend/app/api/watchlist.py`
    *   `backend/app/services/account_service.py`
    *   `backend/app/services/trading_service.py`
    *   `backend/app/services/technical_analysis_service.py`
    *   `backend/app/websocket/connection.py`
    *   `backend/app/websocket/manager.py`
    *   ... (그 외 모든 관련 파일)
*   **변경 내용**:
    *   `import logging` 구문을 제거합니다.
    *   `logger = logging.getLogger(__name__)` 구문을 제거합니다.
    *   파일 상단에 `from loguru import logger`를 추가합니다.

### Phase 5: 검증 및 문서화
**목표**: 변경된 로깅 시스템이 정상적으로 동작하는지 확인하고, 관련 문서를 업데이트합니다.

**수정 및 추가 필요한 파일:**
*   `docs/execution/impl20250911_logging.md`
    *   문서 최상단에 "본 문서는 '1010.logging.plan.md' 계획에 의해 대체되었음"을 명시하여 아카이브합니다.
*   `README.md` 또는 신규 `docs/ops/logging.md`
    *   새로운 로깅 시스템의 구조, 환경 변수 설정법, 로그 확인 방법 등을 기술합니다.
