# 실시간 분봉(OHLCV) 생성 상세 계획

## 0. 요약
- KIS 체결 WebSocket(`H0STCNI0`)만으로 실시간 분봉(시가/고가/저가/종가/거래량)을 집계하고, REST 호출은 초기 로딩·갭 보정 용도로 한정한다.
- 백엔드 `RealtimeDataService`에 분봉 상태 저장소를 추가하고, 체결 틱을 1분 단위로 롤링한 뒤 WebSocket 브로드캐스트(`minute_candle_update`) 및 캐시 반영을 동시에 수행한다.
- 프론트엔드는 기존 REST 기반 훅(`useHistoricalChartData`)과 신규 실시간 훅(`useRealtimeMinuteCandles`)을 결합해 마지막 캔들을 즉시 반영한다.

## 1. 현재 파이프라인 및 요구사항 정리

| 구분 | REST API (FHKST03010200 등) | WebSocket (H0TCNT0, H0STCNI0 등) |
| --- | --- | --- |
| 용도 | 과거~현재 구간 정적 분봉 조회 | 틱 단위 실시간 체결 데이터 수신 |
| 응답 속도 | 1초 이상, 분당 반복 시 부담 | 밀리초 단위 |
| 과거 데이터 | 가능 (당일 포함) | 불가 |
| 분봉 생성 | 기준값 제공 (이미 가공된 분봉) | 체결가 + 시간 + 수량으로 직접 집계 필요 |
| 추천 방식 | 초기 차트 로딩, Gap 보정 | 실시간 분봉 생성/업데이트 |

> **핵심 질문:** WebSocket만으로 분봉 생성 가능한가?  
> **답변:** 가능. 체결가격(`현재가`), 체결시간(`주식체결시간`), 체결수량(`체결거래량`)이 함께 제공되므로, 분 단위 집계로 OHLCV 생성이 가능하다.

- **백엔드/인프라**

## 3. 백엔드 상세 구현 계획

### 3.1 체결 데이터 파싱 개선 (`backend/app/domestic_websocket.py`)

#### 3.1.0 H0STCNI0 원시 메시지/필드 구조
- **실제 샘플 (모의 계좌, 삼성전자)**  
  `005930^093000^62200^100^2^200^0.32^62200^62100^300^200^1^50000^48000^1.12^1200000^74500000000^62000^62500^61800^109`
- **KIS 헤더 정의 (`docs/KIS-API/KIS-ws-H0STCNI0.spec.md`)**
  ```python
  H0STCNI0_HEADER = [
      "symbol", "tr_time", "stck_prpr", "stck_cntg_vol", "prdy_vrss_sign",
      "prdy_vrss", "prdy_ctrt", "askp", "bidp", "askp_rsqn",
      "bidp_rsqn", "new_mkop_cls_code", "total_askp_rsqn", "total_bidp_rsqn", "vol_tnrt",
      "vol", "value", "open", "high", "low", "seq"
  ]

  def parse_h0stcni0_payload(raw: str) -> Dict[str, str]:
      values = raw.split("^")
      return dict(zip(H0STCNI0_HEADER, values))
  ```
- **OHLC 집계에 필요한 핵심 필드**
  - `stck_prpr` (index 2) → 틱 가격
  - `tr_time` (index 1) → 분 구분 키
  - `stck_cntg_vol` (index 3) → 틱 거래량 (`trade_volume`)
  - `vol` (index 15) → 누적 거래량 (`acc_volume`) 보정용

#### 3.1.1 [기존 함수 확장] `receive_realtime_tick_domestic`
- **목적:** 체결 시간/가격/거래량/누적 거래량을 모두 반환하도록 구조 확장.
- **의사코드:**
  ```python
  def receive_realtime_tick_domestic(raw: str) -> dict:
      fields = raw.split("^")
      return {
          "stock_code": fields[0],                 # symbol
          "executed_time": fields[1],              # tr_time (HHMMSS)
          "price": int(fields[2]) if fields[2] else 0,
          "trade_volume": int(fields[3]) if len(fields) > 3 and fields[3] else 0,
          "change_sign": fields[4] if len(fields) > 4 else "",
          "change": int(fields[5]) if len(fields) > 5 and fields[5] else 0,
          "change_rate": float(fields[6]) if len(fields) > 6 and fields[6] else 0.0,
          "ask_price": int(fields[7]) if len(fields) > 7 and fields[7] else 0,
          "bid_price": int(fields[8]) if len(fields) > 8 and fields[8] else 0,
          "ask_qty": int(fields[9]) if len(fields) > 9 and fields[9] else 0,
          "bid_qty": int(fields[10]) if len(fields) > 10 and fields[10] else 0,
          "market_code": fields[11] if len(fields) > 11 else "",
          "total_ask_qty": int(fields[12]) if len(fields) > 12 and fields[12] else 0,
          "total_bid_qty": int(fields[13]) if len(fields) > 13 and fields[13] else 0,
          "volume_ratio": float(fields[14]) if len(fields) > 14 and fields[14] else 0.0,
          "acc_volume": int(fields[15]) if len(fields) > 15 and fields[15] else 0,
          "acc_value": int(fields[16]) if len(fields) > 16 and fields[16] else 0,
          "open_price": int(fields[17]) if len(fields) > 17 and fields[17] else 0,
          "high_price": int(fields[18]) if len(fields) > 18 and fields[18] else 0,
          "low_price": int(fields[19]) if len(fields) > 19 and fields[19] else 0,
          "sequence": int(fields[20]) if len(fields) > 20 and fields[20] else 0,
          "raw_payload": raw,
          "received_at": datetime.utcnow().isoformat(),
      }
  ```
- **거래량 처리 원칙:** `trade_volume`이 0이거나 비어 있으면 이전 틱과의 `acc_volume` 차이를 사용해 추정하고, 음수/이상치인 경우 로그 경고 후 0으로 보정한다.
- **후속 처리:** Queue에 넣는 딕셔너리 키 이름을 영문 스네이크케이스로 통일하고(`stock_code`, `executed_time`, ...), `raw_payload`도 포함하여 디버깅 및 샘플 로그에 활용한다.

#### 3.1.2 [보조 함수 추가] `parse_kis_time`
- 체결 시간(`HHMMSS`)을 `datetime` (KST)로 변환하는 헬퍼 추가.
  ```python
  def parse_kis_time(time_str: str) -> datetime:
      base = datetime.now(tz=KST)
      return base.replace(hour=int(time_str[:2]), minute=int(time_str[2:4]), second=int(time_str[4:6]), microsecond=0)
  ```

### 3.2 분봉 상태 집계 및 브로드캐스트 (`backend/app/services/realtime_service.py`)

#### 3.2.1 [새 데이터 구조] `backend/app/models/realtime_minute.py`
- `MinuteCandleState` 데이터클래스 생성.
  ```python
  @dataclass
  class MinuteCandleState:
      minute_key: str          # "YYYY-MM-DDTHH:MM:00"
      open: float
      high: float
      low: float
      close: float
      volume: int
      start_ts: datetime
      last_tick_ts: datetime

      def apply_tick(self, price: float, volume: int, tick_ts: datetime) -> None:
          self.high = max(self.high, price)
          self.low = min(self.low, price)
          self.close = price
          self.volume += volume
          self.last_tick_ts = tick_ts
  ```

#### 3.2.2 [생성자 확장] `RealtimeDataService.__init__`
- 상태 저장소 및 락 추가.
  ```python
  self.minute_candle_state: Dict[str, MinuteCandleState] = {}
  self.minute_state_lock = asyncio.Lock()
  self.minute_state_ttl = timedelta(minutes=10)  # 오래된 항목 정리
  ```

#### 3.2.3 [핵심 로직 추가] `_handle_tick_data`
- **흐름:**
  1. 체결 데이터 추출 (`stock_code`, `price`, `trade_volume`, `executed_time`).
  2. 체결시간을 기반으로 분 단위 키 계산 (`minute_key = executed_ts.strftime("%Y-%m-%dT%H:%M:00")`).
  3. 상태 저장소에 해당 종목의 현재 분 상태가 있으면 업데이트, 없거나 분이 바뀌면 플러시 후 새 상태 생성.
  4. 브로드캐스트 페이로드 생성 후 `ConnectionManager.broadcast` 호출.
  5. 분 경계가 넘어갈 때, 완성된 캔들을 비동기 이벤트로 큐잉해 기존 `TradingService.update_minute_candle`로 전달하거나 향후 백업 플로우에서 재사용할 수 있도록 저장.
- **의사코드:**
  ```python
  async def _handle_tick_data(self, message: Dict[str, Any]):
      data = message.get("data", {})
      stock_code = data.get("stock_code")
      price = float(data.get("price"))
      volume = int(data.get("trade_volume", 0))
      executed_ts = parse_kis_time(data.get("executed_time"))
      minute_key = executed_ts.strftime("%Y-%m-%dT%H:%M:00")

      async with self.minute_state_lock:
          state = self.minute_candle_state.get(stock_code)

          if state and state.minute_key != minute_key:
              await self._flush_closed_candle(stock_code, state)
              state = None

          if not state:
              state = MinuteCandleState(
                  minute_key=minute_key,
                  open=price,
                  high=price,
                  low=price,
                  close=price,
                  volume=volume,
                  start_ts=executed_ts,
                  last_tick_ts=executed_ts,
              )
              self.minute_candle_state[stock_code] = state
          else:
              state.apply_tick(price, volume, executed_ts)

          await self._broadcast_minute_snapshot(stock_code, state)
  ```

#### 3.2.4 [보조 메서드] `_flush_closed_candle`
- **역할:** 분 경계가 넘어간 직전 분 상태를 확정하고, 필요 시 이벤트 큐를 통해 기존 저장 로직에 전달.
- **의사코드:**
  ```python
  async def _flush_closed_candle(self, stock_code: str, state: MinuteCandleState) -> None:
      candle = ChartCandle(
          timestamp=state.minute_key,
          open=state.open,
          high=state.high,
          low=state.low,
          close=state.close,
          volume=state.volume,
      )
      await self._enqueue_candle_for_persistence(stock_code, candle)
      await self.connection_manager.broadcast({
          "type": "minute_candle_finalize",
          "stock_code": stock_code,
          "data": candle.model_dump(),
      })
  ```
- **Persistence 전략:** `_enqueue_candle_for_persistence`는 단순 Queue(예: `asyncio.Queue`)에 넣고, 별도 소비 코루틴에서 FastAPI dependency를 통해 `TradingService.update_minute_candle`을 호출한다. 이렇게 하면 직접적인 서비스 주입 없이 기존 캐시/REST 파이프라인을 재사용할 수 있다.

#### 3.2.5 [보조 메서드] `_broadcast_minute_snapshot`
- **역할:** 현재 진행 중인 분봉 스냅샷 전송 (`minute_candle_update`).
  ```python
  async def _broadcast_minute_snapshot(self, stock_code: str, state: MinuteCandleState):
      payload = {
          "type": "minute_candle_update",
          "stock_code": stock_code,
          "data": {
              "timestamp": state.minute_key,
              "open": state.open,
              "high": state.high,
              "low": state.low,
              "close": state.close,
              "volume": state.volume,
              "last_tick": state.last_tick_ts.isoformat(),
          }
      }
      await self.connection_manager.broadcast(payload)
  ```

#### 3.2.6 [정리 작업] `_drain_stale_states`

### 4.1 타입/상수 정의

  ```ts
  }
  ```
- `WS_MESSAGE_TYPES`에 `MINUTE_CANDLE_UPDATE`, `MINUTE_CANDLE_FINALIZE` 추가.

### 4.2 WebSocket 매니저 (`stock-trading-ui/src/lib/websocket.ts`)

- `handleMessage` switch-case에 새 타입 등록.
- `subscribeToMinuteCandles(stockCode, callback)` 헬퍼 추가.
  ```ts
  export function subscribeToMinuteCandles(callback: (payload: MinuteCandlePayload & { stockCode: string }) => void): () => void {
    const listener = (data: MinuteCandlePayload) => callback({ ...data, stockCode: data.stock_code });
    wsManager.on(WS_MESSAGE_TYPES.MINUTE_CANDLE_UPDATE, listener);
    return () => wsManager.off(WS_MESSAGE_TYPES.MINUTE_CANDLE_UPDATE, listener);
  }
  ```
- 분봉 finalize는 필요 시 다른 훅에서 사용하도록 별도 helper 제공.

### 4.3 실시간 분봉 전용 훅 (`stock-trading-ui/src/hooks/useRealtimeMinuteCandles.ts`)

- **신규 훅 도입:** WebSocket을 구독해 최신 분봉을 별도로 관리한다.
  ```ts
  export function useRealtimeMinuteCandles(stockCode: string, enabled = true) {
    const [currentCandle, setCurrentCandle] = useState<ChartCandle | null>(null);

    useEffect(() => {
      if (!enabled) return;
      const unsubscribe = subscribeToMinuteCandles((payload) => {
        if (payload.stock_code !== stockCode) return;
        setCurrentCandle({
          timestamp: payload.data.timestamp,
          open: payload.data.open,
          high: payload.data.high,
          low: payload.data.low,
          close: payload.data.close,
          volume: payload.data.volume,
        });
      });
      return unsubscribe;
    }, [stockCode, enabled]);

    return currentCandle;
  }
  ```
- **Finalize 대응:** `minute_candle_finalize` 메시지에 대해서도 동일 훅에서 처리하거나, 별도 콜백으로 전달해 REST 폴링 트리거를 조정한다.

### 4.4 차트 컴포넌트 (`RealtimeCandlestickChart`, `UniversalChart`)
- `useHistoricalChartData`에서 받은 배열과 `useRealtimeMinuteCandles` 결과를 `useMemo`로 병합한다.
  ```ts
  const historicalData = useHistoricalChartData(...);
  const realtimeCandle = useRealtimeMinuteCandles(stockCode, timeframe === 'minute');

  const chartData = useMemo(() => {
    if (!realtimeCandle || historicalData.length === 0) return historicalData;
    const last = historicalData[historicalData.length - 1];
    if (last.timestamp.slice(0, 16) === realtimeCandle.timestamp.slice(0, 16)) {
      return [...historicalData.slice(0, -1), realtimeCandle];
    }
    return historicalData;
  }, [historicalData, realtimeCandle]);
  ```
- REST 폴링/무한 스크롤 로직은 기존 훅이 책임지므로 단일 책임 원칙을 유지한다.

## 5. 운영 및 모니터링 고려사항
- `MinuteCandleState` 갯수 및 업데이트 간격을 `MetricsCollector`에 기록 (`minute_candle_update_count`, `minute_candle_broadcast_latency` 등).
- Queue backlog 발생 시 분봉 유실 여부 로깅 (`dropped_messages_count`).
- 실패 시 fallback: 1분마다 REST `/minute/current` 호출로 보정 (프론트엔드에서 옵션 제공).
