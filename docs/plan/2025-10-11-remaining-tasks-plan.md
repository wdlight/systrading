# 포트폴리오 기능 구현 후 남은 작업 계획 (2025-10-11)

## 📋 개요

이 문서는 포트폴리오 이력 조회 기능의 Phase 1(MVP) 및 Phase 2(최적화) 구현과 안정화 작업이 완료된 후, 진행할 수 있는 다음 작업 목록을 우선순위 순으로 정리한 것입니다.

---

## 📝 남은 작업 목록 (Remaining Task List)

### 1. 최종 검증 및 모니터링 (가장 높은 우선순위)

안정화된 서버 환경에서 최적화 기능들이 의도대로 동작하는지 최종 검증하는 단계입니다.

-   **스케줄러 및 스냅샷 생성 확인**:
    -   **내용**: `main.py` 서버를 실행하고 5분 이상 유지하여, `apscheduler`가 `backend/data/snapshots/` 디렉토리에 스냅샷 파일을 주기적으로 생성하는지 확인합니다.
    -   **목표**: 백그라운드 작업의 안정성을 최종 검증합니다.

-   **API 엔드포인트 캐싱 확인**:
    -   **내용**: 서버가 실행 중인 상태에서, `curl`과 같은 도구를 사용해 `http://localhost:8000/api/portfolio/history?period=1M`를 두 번 연속 호출합니다.
    -   **목표**: 두 번째 호출 시 서버 로그에 "캐시 사용" 메시지가 출력되고 응답 속도가 현저히 빨라지는지 확인하여 Redis 캐시 적용을 최종 검증합니다.

### 2. 테스트 코드 보강

향후 발생할 수 있는 유사한 버그의 재발을 방지하기 위해 테스트 코드를 강화합니다.

-   **현금 계산 회귀 테스트 추가**:
    -   **내용**: 보유 주식 없이 현금만 있는 계좌의 API 응답을 모의(mock)로 만들어, 현금 계산 로직이 정확히 동작하는지 검증하는 단위 테스트 케이스를 추가합니다.
    -   **목표**: 핵심 로직의 안정성을 높이고, 향후 변경에 대한 안전장치를 마련합니다.

### 3. Phase 3 안정화

원본 계획 문서의 마지막 단계로, 서비스의 운영 안정성을 높이는 작업입니다.

-   **구조화된 로깅 도입**:
    -   **내용**: `loguru` 설정을 `logging_config.py`로 분리하여, 날짜별 로그 파일 생성, 에러 로그 분리 등 운영 환경에 적합한 로깅 시스템을 구축합니다.
    -   **목표**: 운영 중 문제 발생 시 원인 추적을 용이하게 합니다.

### 4. 기능 개선 및 프론트엔드 연동

-   **벤치마크 계산 로직 정교화**:
    -   **내용**: `PortfolioAnalyticsService`의 `_align_benchmark` 메소드에 선형 보간(linear interpolation) 로직을 추가하여 벤치마크 데이터의 정확도를 높입니다.
    -   **목표**: 포트폴리오와 벤치마크 수익률 비교의 정확성을 향상시킵니다.

-   **프론트엔드 연동**:
    -   **내용**: 프론트엔드 포트폴리오 차트가 실제 `GET /api/portfolio/history` API를 호출하여 받은 데이터로 차트를 그리도록 최종 연동합니다.
    -   **목표**: 구현된 백엔드 기능의 최종 목표인 사용자향 시각화 기능을 완성합니다.
