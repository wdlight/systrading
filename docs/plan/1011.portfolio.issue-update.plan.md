## 🛠️ 이슈 수정 계획 (Modification Plan)

### 1. (치명적) `available_cash` 계산 오류 수정

-   **문제점**: `korea_invest.py`에서 `get_account_balance`가 (총평가금액 - 투자원금)을 현금으로 잘못 계산하여, 포트폴리오 전체 계산이 왜곡되고 있습니다.
-   **보강된 수정 계획**:
    1.  **파일**: `brokers/korea_investment/ki_api.py`
    2.  **메소드**: `get_acct_balance`
    3.  **작업 내용**:
        -   메소드의 반환 형식을 `(총평가금액, 예수금, 보유종목 DataFrame)` 튜플로 변경합니다.
        -   API 응답 `output2`에서 `dnca_tot_amt`(예수금총액) 필드를 파싱합니다.
        -   이때, `dnca_tot_amt` 값이 문자열이거나 없을 경우를 대비해 `int(r2[0].get('dnca_tot_amt', 0) or 0)`과 같이 안전하게 정수형으로 변환하고, 실패 시 0을 반환하도록 처리합니다.

    4.  **파일**: `backend/app/core/korea_invest.py`
    5.  **메소드**: `get_account_balance`
    6.  **작업 내용**:
        -   `get_acct_balance` 호출 후, 세 개의 값을 언패킹하여 `total_value, available_cash, df` 변수에 각각 할당받도록 수정합니다.
        -   기존의 부정확한 현금 계산 로직을 완전히 삭제하고, API로부터 직접 받은 `available_cash` 값을 그대로 사용합니다.

    7.  **회귀 테스트 추가**:
        -   **파일**: `backend/tests/test_korea_invest_service.py` (또는 신규 생성)
        -   **내용**:
            -   **Test Case 1**: `dnca_tot_amt` 필드가 정상적으로 포함된 모의(mock) API 응답을 생성하고, `get_account_balance`가 정확한 현금 값을 반환하는지 검증합니다.
            -   **Test Case 2**: `dnca_tot_amt` 필드가 **없는** 모의 API 응답을 생성하고, `get_account_balance`가 오류 없이 `available_cash`를 0으로 처리하는지 검증합니다.

### 2. (Major) 벤치마크 조회 실패 시 빈 응답 반환 문제

-   **문제점**: `portfolio_analytics_service.py`에서 벤치마크 조회에 실패하면 빈 리스트가 반환되어, 최종 결과까지 비어버리는 문제입니다.
-   **보강된 수정 계획**:
    1.  **파일**: `backend/app/services/benchmark_service.py`
    2.  **메소드**: `normalize_to_portfolio`
    3.  **작업 내용**:
        -   메소드 최상단에 `if not benchmark_values: return []` 구문을 추가하여, 입력 리스트가 비어있을 경우 즉시 빈 리스트를 반환하도록 방어 코드를 추가합니다.

    4.  **파일**: `backend/app/services/portfolio_analytics_service.py`
    5.  **메소드**: `get_portfolio_history`
    6.  **작업 내용**:
        -   벤치마크 데이터를 가져온 후, `if not normalized_benchmark or len(normalized_benchmark) != len(portfolio_values):` 와 같이 **빈 리스트인 경우**와 **길이가 불일치하는 경우**를 모두 체크하는 조건문을 추가합니다.
        -   해당 조건에 걸릴 경우, `logger.warning(f"벤치마크 데이터 길이 불일치. 포트폴리오: {len(portfolio_values)}, 벤치마크: {len(normalized_benchmark)}. 평탄한 기준선으로 대체합니다.")` 와 같이 실제 길이를 포함한 상세한 경고 로그를 남깁니다.
        -   폴백(fallback) 로직으로, `portfolio_values[0]['value']` 값을 `len(portfolio_values)` 개수만큼 복제하여 `normalized_benchmark`에 할당합니다.

### 3. (Major) 스냅샷 재생 시 당일 거래 누락 문제

-   **문제점**: 스냅샷 생성 날짜와 같은 날의 거래 내역이 무시되는 문제입니다.
-   **보강된 수정 계획**:
    1.  **파일**: `backend/app/services/snapshot_manager.py`
    2.  **메소드**: `replay_from_snapshot`
    3.  **작업 내용**:
        -   거래 내역 루프 안에서 `try...except` 블록을 사용하여 시간 비교 로직을 감쌉니다.
        -   **`try` 블록**:
            -   `snapshot['timestamp']`와 `trade.trade_time` (없을 경우 '000000'으로 처리)을 사용하여 각각 `datetime` 객체를 생성합니다.
            -   `trade_datetime <= snapshot_datetime` 조건으로 **정확한 시간까지 비교**하여 스냅샷 시점 이전의 거래만 건너뛰도록 합니다.
        -   **`except (KeyError, ValueError)` 블록**:
            -   `snapshot['timestamp']` 필드가 없거나 날짜/시간 형식이 잘못된 예외 상황을 처리합니다.
            -   `logger.warning`으로 "정확한 시간 비교 실패, 날짜 기준으로만 필터링합니다." 라는 로그를 남깁니다.
            -   기존의 날짜 기반 비교 로직(`trade_date_dt <= snapshot_date_dt`)을 **폴백(fallback)으로 실행**하여 안정성을 확보합니다.
