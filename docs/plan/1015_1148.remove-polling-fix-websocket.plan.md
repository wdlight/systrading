# Remove Polling and Fix WebSocket Subscription

## Problem Analysis

현재 시스템의 문제점:

1. **잘못된 해결책**: `useOrderBook.ts`의 147-172번 라인에서 `setInterval`을 사용한 폴링 로직이 추가됨
   - 1초마다 REST API를 호출하여 서버 부하 증가
   - API 호출 제한 위험
   - WebSocket의 장점을 전혀 활용하지 못함

2. **근본 원인**: 프론트엔드가 WebSocket 구독 메시지를 보내지만, 백엔드의 `ConnectionManager.stock_subscribers`에 제대로 등록되지 않음
   - 백엔드 WebSocket 엔드포인트(`/ws`)는 이미 `subscribe`/`unsubscribe` 메시지를 처리하도록 구현됨 (main.py:266-271)
   - 프론트엔드는 WebSocket 메시지를 보내고 있음 (useOrderBook.ts:74-82, 107-113)
   - 하지만 실제로는 데이터가 전달되지 않음

## Root Cause

코드 검토 결과, 백엔드와 프론트엔드의 WebSocket 구독 로직은 이미 구현되어 있습니다. 문제는:

1. **폴링 로직이 추가되면서** WebSocket 구독이 제대로 작동하지 않는 것처럼 보이게 됨
2. 폴링 로직이 WebSocket 메시지 수신을 방해하거나, 개발자가 WebSocket이 작동하지 않는다고 오해하게 만듦

## Solution

### Step 1: Remove Polling Logic (CRITICAL)

**File**: `stock-trading-ui/src/hooks/useOrderBook.ts`

**Remove lines 147-172**: 폴링 로직 전체 삭제

```typescript
// 삭제할 코드:
// 폴링으로 주기적으로 호가 데이터 업데이트 (WebSocket 대체)
useEffect(() => {
  if (!isSubscribed) return;

  console.log(`🔄 호가 데이터 폴링 시작: ${stockCode} (1초 간격)`);

  const pollingInterval = setInterval(async () => {
    try {
      const data = await apiClient.getCurrentOrderBook(stockCode);
      console.log(`🔄 호가 데이터 폴링 업데이트: ${stockCode}`, {
        current_price: data.current_price,
        ask1: data.asks[0]?.price,
        bid1: data.bids[0]?.price
      });
      setOrderBook(data);
      setError(null);
    } catch (err) {
      console.error('폴링 중 호가 데이터 로드 오류:', err);
    }
  }, 1000); // 1초마다 업데이트

  return () => {
    console.log(`⏹️ 호가 데이터 폴링 중지: ${stockCode}`);
    clearInterval(pollingInterval);
  };
}, [stockCode, isSubscribed]);
```
