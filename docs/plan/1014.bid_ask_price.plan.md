# 📘 실시간 매수/매도 호가 조회 가이드 (`realtime_ask_bid_price.md`)

한국투자증권 OpenAPI를 통해 **특정 종목의 실시간 매수/매도 호가**를 구독하는 방법에 대해 단계별로 설명합니다.  
웹소켓 기반 API를 활용하며, Python 예제와 함께 초보자를 위한 구성으로 안내드립니다.

---

## ✅ 1. 실시간 호가란?

> 호가란?
- 매수: 얼마에 사고 싶은지 제시한 가격
- 매도: 얼마에 팔고 싶은지 제시한 가격

실시간 호가 API를 통해 각 종목에 대해 **10단계까지의 매수/매도 호가와 잔량** 정보를 수신할 수 있습니다.

---

## ✅ 2. 주요 API 정보

| 항목 | 내용 |
|------|------|
| API 방식 | 웹소켓 (WebSocket) |
| 채널 ID | `H0STASP0` (국내주식 통합 호가) |
| 대상 종목 | KRX 및 NXT 통합 |
| 전송방식 | 실시간 Push (서버 → 클라이언트) |
| 통신주소 | `wss://openapi.koreainvestment.com:9443/websocket` |

## ✅ 4. Python 예제 코드

```python
import websocket
import json
import threading

def on_message(ws, message):
    data = json.loads(message)
    print("📩 수신 데이터:", json.dumps(data, indent=2, ensure_ascii=False))

def on_error(ws, error):
    print("❌ 오류 발생:", error)

def on_close(ws, close_status_code, close_msg):
    print("🔌 연결 종료")

def on_open(ws):
    print("✅ 연결 성공")

    msg = {
        "header": {
            "approval_key": "발급받은_웹소켓_접속키를_입력하세요",
            "custtype": "P",
            "tr_type": "1",
            "content-type": "utf-8"
        },
        "body": {
            "input": {
                "tr_id": "H0STASP0",
                "tr_key": "005930"  # 예시: 삼성전자
            }
        }
    }

    ws.send(json.dumps(msg))

def run_websocket():
    websocket.enableTrace(False)
    ws = websocket.WebSocketApp(
        "wss://openapi.koreainvestment.com:9443/websocket",
        on_open=on_open,
        on_message=on_message,
        on_error=on_error,
        on_close=on_close
    )
    ws.run_forever()

thread = threading.Thread(target=run_websocket)
thread.start()
```

# 한국투자증권 WebSocket 데이터 수신 루틴 상세 계획

## 목표

백엔드에서 한국투자증권(KIS) WebSocket API를 통해 실시간 데이터를 수신하는 전체 프로세스를 초보 개발자도 이해할 수 있도록 상세히 문서화합니다.

## 문서 구조

### 1부: WebSocket 데이터 수신 개요

#### 1.1 전체 아키텍처

```
[FastAPI 메인 프로세스]
    ↓ (multiprocessing.Process 생성)
[domestic_websocket 자식 프로세스]
    ↓ (WebSocket 연결)
[한국투자증권 WebSocket 서버]
    ↓ (실시간 데이터 Push)
[domestic_websocket 자식 프로세스]
    ↓ (multiprocessing.Queue)
[FastAPI 메인 프로세스 - RealtimeDataService]
    ↓ (처리 및 브로드캐스트)
[Frontend 클라이언트들]
```

#### 1.2 왜 별도 프로세스를 사용하는가?

**문제점**:

- Python의 GIL (Global Interpreter Lock) 때문에 하나의 프로세스에서 CPU 집약적 작업과 I/O 작업을 동시에 효율적으로 처리하기 어려움
- WebSocket 연결은 블로킹 I/O 작업으로 메인 FastAPI 서버의 성능에 영향을 줄 수 있음

**해결책**:

- `multiprocessing` 모듈을 사용하여 WebSocket 연결을 별도 프로세스로 분리
- 프로세스 간 통신(IPC)은 `multiprocessing.Queue` 사용
- 메인 프로세스는 FastAPI 요청 처리에 집중
- 자식 프로세스는 WebSocket 데이터 수신에 집중

### 2부: 프로세스 생성 및 초기화

#### 2.1 메인 프로세스에서 WebSocket 프로세스 시작

**파일**: `backend/app/main.py`

**lifespan 함수에서 프로세스 시작**:

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    """애플리케이션 생명주기 관리"""
    logger.info("FastAPI 애플리케이션 초기화를 시작합니다.")
    
    # 1. KoreaInvestAPIService 초기화
    korea_invest_service = await get_korea_invest_service()
    
    # 2. Queue 생성 (프로세스 간 통신용)
    ws_req_queue = Queue()      # 메인 → WebSocket 프로세스 (구독 요청)
    ws_result_queue = Queue()   # WebSocket 프로세스 → 메인 (수신 데이터)
    
    # 3. WebSocket 프로세스 시작
    from multiprocessing import Process
    from app.domestic_websocket import run_websocket
    
    ws_process = Process(
        target=run_websocket,
        args=(
            korea_invest_service.api,  # KoreaInvestAPI 인스턴스
            korea_invest_service.ws_url,  # WebSocket URL
            ws_req_queue,
            ws_result_queue
        ),
        daemon=True  # 메인 프로세스 종료 시 함께 종료
    )
    ws_process.start()
    logger.info(f"domestic_websocket 프로세스를 시작했습니다 (PID: {ws_process.pid}).")
    
    # 4. RealtimeDataService 초기화 및 시작
    realtime_service = RealtimeDataService(
        korea_invest_service=korea_invest_service,
        connection_manager=connection_manager,
        ws_result_queue=ws_result_queue  # Queue 전달
    )
    await realtime_service.start()
    
    yield  # 애플리케이션 실행
    
    # 종료 시 정리
    await realtime_service.stop()
    ws_process.terminate()
    ws_process.join(timeout=5)
```

**핵심 포인트**:

1. `Queue()`: 프로세스 간 안전한 데이터 전달을 위한 FIFO 큐
2. `Process()`: 새로운 Python 프로세스 생성
3. `daemon=True`: 부모 프로세스 종료 시 자동 종료
4. `start()`: 프로세스 실행 시작

#### 2.2 Queue의 역할

**ws_req_queue** (요청 큐):

- 방향: 메인 프로세스 → WebSocket 프로세스
- 용도: 실시간 구독/해제 요청 전달
- 메시지 형식:
```python
{
    "action_id": "실시간호가등록",  # 또는 "실시간호가해제", "실시간체결등록" 등
    "종목코드": "005930"
}
```


**ws_result_queue** (결과 큐):

- 방향: WebSocket 프로세스 → 메인 프로세스
- 용도: 수신한 실시간 데이터 전달
- 메시지 형식:
```python
{
    "action_id": "실시간호가",  # 데이터 타입
    "종목코드": "005930",
    "data": {
        "매도1호가": 71200,
        "매도1호가수량": 450,
        # ... 호가 데이터
    }
}
```


### 3부: WebSocket 프로세스 상세 분석

#### 3.1 프로세스 진입점

**파일**: `backend/app/domestic_websocket.py`

**run_websocket 함수**:

```python
def run_websocket(korea_invest_api, ws_url, ws_req_queue, ws_result_queue):
    """
    WebSocket 프로세스의 진입점
    
    Args:
        korea_invest_api: KoreaInvestAPI 인스턴스
        ws_url: WebSocket 서버 URL
        ws_req_queue: 구독 요청 수신용 Queue
        ws_result_queue: 데이터 전송용 Queue
    """
    # 1. 새 이벤트 루프 생성 (자식 프로세스는 새 루프 필요)
    loop = asyncio.get_event_loop()
    
    # 2. connect 코루틴 실행
    loop.run_until_complete(
        connect(korea_invest_api, ws_url, ws_req_queue, ws_result_queue)
    )
    
    # 3. 루프 종료
    loop.close()
```

**왜 새 이벤트 루프가 필요한가?**

- 각 프로세스는 독립적인 asyncio 이벤트 루프를 가져야 함
- 부모 프로세스의 이벤트 루프는 자식 프로세스에서 사용 불가

2. **지수 구독** (KOSPI 001, KOSDAQ 201):

   - 주요 지수의 실시간 변동 수신
   - 현재가, 등락률 등

**루프 구조 설명**:

4. **데이터 처리**: 타입별로 파싱 후 `ws_result_queue`에 전달

### 4부: 데이터 타입별 처리

#### 4.1 데이터 형식 구분

KIS WebSocket은 3가지 형식으로 데이터를 전송:

**1. 실시간 데이터 (data[0] == '0')**:

```
0|H0STCNT0|1|종목코드^체결시간^현재가^...
```

- 구분자: 파이프(`|`)
- 첫 문자가 '0'
- TR_ID로 데이터 타입 구분

**2. 암호화된 체결 통보 (data[0] == '1')**:

```
1|H0STCNI0|1|base64_encrypted_data
```

- AES256으로 암호화된 주문/체결 정보
- 복호화 필요

**3. JSON 응답 (그 외)**:

```json
{
  "header": {"tr_id": "H0STCNI0"},
  "body": {"rt_cd": "0", "msg1": "SUCCESS"}
}
```

- 구독 성공/실패 응답
- PINGPONG 하트비트
- 에러 메시지

#### 4.2 실시간 데이터 처리 (data[0] == '0')

if data[0] == '0':

**receive_realtime_tick_domestic 함수**:

def receive_realtime_tick_domestic(data):
    """
    실시간 체결 데이터 파싱
    
    데이터 형식:
    종목코드^체결시간^현재가^전일대비부호^전일대비^...
    """
    values = data.split('^')
    
    return {
        "종목코드": values[0],
        "체결시간": values[1],
        "현재가": int(values[2]) if values[2] else 0,
        # 필요한 필드만 추출
    }
```

def receive_realtime_hoga_domestic(data):
    """
    실시간 호가 데이터 파싱
    
    데이터 형식:

def receive_signing_notice(data, key, iv, account_num, ws_result_queue):
    """
    암호화된 주문 체결 통보 처리
    
    Args:
        data: Base64 인코딩된 AES256 암호문
        key: AES256 복호화 키 (32자)
        iv: 초기화 벡터 (16자)
        account_num: 계좌번호 (검증용)
        ws_result_queue: 결과 전달용 Queue
    """
    # 1. AES256 복호화
    aes_dec_str = aes_cbc_base64_dec(key, iv, data)
    
    # 2. 데이터 파싱
    values = aes_dec_str.split('^')
    
    계좌번호 = values[1]
    # 3. 계좌번호 검증
    if 계좌번호[:8] != account_num:
        return  # 다른 계좌의 체결 통보
    
    # 4. 거부 여부 확인
    거부여부 = values[12]
    if 거부여부 != "0":
        logger.info("주문 거부")
        return
    
    # 5. 체결 정보 추출
    체결여부 = values[13]  # 1: 주문 접수, 2: 체결
    종목코드 = values[8]
    종목명 = values[18]
    시간 = values[11]
    주문수량 = int(values[16]) if values[16] else 0
    체결수량 = int(values[9]) if 체결여부 == "2" else 0
    
    # 매수/매도 구분
    매도매수구분 = values[4]  # 01: 매도, 02: 매수
    정정구분 = values[5]
    
    if 매도매수구분 == '02' and 정정구분 != "0":
        주문구분 = "매수정정"
    elif 매도매수구분 == '01' and 정정구분 != "0":
        주문구분 = "매도정정"
    elif 매도매수구분 == '02':
        주문구분 = "매수"
    elif 매도매수구분 == '01':
        주문구분 = "매도"
    
    # 6. 결과 Queue에 전달
    ws_result_queue.put({
        "action_id": "주문체결통보",
        "시간": 시간,
        "종목코드": 종목코드,
        "종목명": 종목명,
        "주문수량": 주문수량,
        "체결수량": 체결수량,
        "주문구분": 주문구분,
        "체결여부": 체결여부
    })
```

**AES256 복호화 함수**:

```python
def aes_cbc_base64_dec(key, iv, cipher_text):
    """
    AES256-CBC 모드 Base64 복호화
    
    Args:
        key: 32자 문자열
        iv: 16자 문자열
        cipher_text: Base64 인코딩된 암호문
    
    Returns:
        복호화된 평문 문자열
    """
    from Crypto.Cipher import AES
    from Crypto.Util.Padding import unpad
    from base64 import b64decode
    
    # 1. AES 객체 생성
    cipher = AES.new(
        key.encode('utf-8'),
        AES.MODE_CBC,
        iv.encode('utf-8')
    )
    
    # 2. Base64 디코딩
    encrypted_data = b64decode(cipher_text)
    
    # 3. 복호화
    decrypted_data = cipher.decrypt(encrypted_data)
    
    # 4. 패딩 제거
    unpadded_data = unpad(decrypted_data, AES.block_size)
    
    # 5. 문자열 변환
    return unpadded_data.decode('utf-8')
```

async def _tr_result_loop(self):
    """
    WebSocket 프로세스로부터 데이터 수신 및 처리
    0.05초(50ms)마다 실행
    """
    while self.is_running:
        try:
            # 1. Queue에서 데이터 가져오기 (비블로킹)
            if not self.ws_result_queue.empty():
                result_data = self.ws_result_queue.get()
                action_id = result_data.get("action_id")
                
                # 2. 데이터 타입별 처리
                if action_id == "실시간체결":
                    await self._handle_tick_data(result_data)
                
                elif action_id == "실시간호가":
                    await self._handle_hoga_data(result_data)
                
                elif action_id == "주문체결통보":
                    await self._handle_order_notification(result_data)
                
                elif action_id == "실시간지수":
                    await self._handle_index_data(result_data)
                
        except Empty:
            pass  # Queue가 비어있음
        except Exception as e:
            logger.error(f"TR 결과 처리 오류: {e}")
        
        # 3. 50ms 대기
        await asyncio.sleep(0.05)

    # JSON 직렬화 한 번만 수행
