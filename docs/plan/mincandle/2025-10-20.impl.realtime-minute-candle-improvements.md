# 실시간 분봉 캐시 연동 개선 계획

**문서 ID**: `2025-10-20.impl.realtime-minute-candle-improvements`
**작성일**: 2025-10-20
**담당자 대상**: 주니어 백엔드/프론트엔드 개발자

---

## 1. 🎯 개선 목표
- WebSocket으로 확정된 분봉이 캐시(`kordata/{종목코드}/{YYYYMMDD}.json`)에도 즉시 반영되도록 `RealtimeDataService`에 퍼시스턴스 핸들러를 주입한다.
- 프론트엔드가 `minute_candle_finalize` 브로드캐스트를 활용하여 REST 호출 없이도 확정 분봉을 차트 데이터에 합친다.
- 간단한 테스트 및 검증 루틴을 마련해 회귀 없이 배포할 수 있도록 한다.

---

## 2. 🔧 작업 전제 조건
- 백엔드: FastAPI 앱을 실행할 수 있는 환경 (`cd backend && scripts/start_backend.sh`).
- 프론트엔드: `stock-trading-ui` 폴더에서 `npm install`이 완료되어 있어야 함.
- `kordata/` 캐시 디렉터리에 쓰기 권한이 있어야 하며, 테스트 시 기존 파일 덮어쓰기가 일어날 수 있으니 주의할 것.

---

## 3. 📦 구현 계획 (Backend)

### 3.1 퍼시스턴스 핸들러 정의
1. 파일: `backend/app/services/realtime_service.py`
2. 신규 메서드 `_persist_minute_candle` 추가
   - 인수: `stock_code: str`, `candle: ChartCandle`
   - 내부에서 주입받은 `TradingService` 인스턴스를 호출하며, 예외 로깅 포함.
3. 기존 `_minute_persist_handler` 필드를 `Optional[TradingService]` 대신 콜러블 유지하되, 기본 핸들러를 `_persist_minute_candle`로 설정.

### 3.2 FastAPI 초기화 시 주입
1. 파일: `backend/app/main.py`
2. `RealtimeDataService` 생성 직후 `TradingService` 인스턴스를 만들거나 팩토리 함수를 이용해 핸들러를 등록.
   ```python
   trading_service = TradingService(korea_invest_service)
   realtime_service.set_minute_persist_handler(
       lambda code, candle: trading_service.update_minute_candle(
           stock_code=code,
           target_date=datetime.fromisoformat(candle.timestamp),
           candle_data=candle,
       )
   )
   ```
3. `datetime` 임포트 여부 확인 후 없으면 추가.
4. 애플리케이션 종료 시 별도 정리는 불필요하나, 필요 시 `await realtime_service.stop()` 내에서 큐 drain이 끝났는지 확인.

### 3.3 로깅 및 리트라이 (선택)
- 실패 시 경고 로그 남기고 큐에 재적재하지 않는다. (주니어 수준 고려)
- 추후 필요 시 재시도 로직을 별도 티켓으로 분리.

## 4. 💡 구현 계획 (Frontend)

### 4.1 WebSocket 구독 확장
1. 파일: `stock-trading-ui/src/hooks/useRealtimeMinuteCandles.ts`
2. `subscribeToMinuteCandleFinalize`를 함께 구독하여 확정 분봉을 별도 상태로 보관.
3. 새로운 `finalizedCandles` 상태 배열을 추가하고, 동일 종목 메시지일 때 기존 실시간 캔들과 비교해 병합.

### 4.2 차트 데이터 병합 로직 수정
1. 파일: `stock-trading-ui/src/components/trading/RealtimeCandlestickChart.tsx`
2. `finalChartData` 계산 시 `finalizedCandles`(확정) → `baseChartData` → 진행 중 캔들 순으로 결합.
3. 새 finalize가 들어오면 중복 타임스탬프를 교체하고, 최신 시계열 정렬이 유지되는지 확인.

### 4.3 상태 초기화 및 언마운트 처리
- 다른 종목으로 전환 시 `finalizedCandles` 초기화.
- 훅 clean-up에서 finalize 구독 해제.

## 5. ✅ 검증 단계

### 5.1 백엔드 단독 테스트
1. FastAPI 서버 기동 후 특정 종목 WebSocket 틱이 들어오도록 샌드박스 환경 또는 모의 데이터 사용.
2. 분 경계가 넘어갈 때 `logs/minute_candle_samples.log`에 finalize 로그가 찍히는지 확인.
3. `kordata/{종목}/{YYYYMMDD}.json`에서 마지막 캔들이 실시간 가격으로 갱신되었는지 검증.

### 5.2 프론트엔드 수동 테스트
1. `cd stock-trading-ui && npm run dev` 실행.
2. 삼성전자 선택 → 1분 경과 후 finalize 메시지가 들어오면 차트가 REST 재호출 없이 자동으로 확정 캔들로 갱신되는지 확인.
3. 다른 종목 전환 후 다시 돌아와도 finalize된 캔들이 중복되지 않는지 확인.

### 5.3 회귀 방지
- 필요 시 `npm run test`로 기존 프런트 테스트 수행.
- 백엔드 pytest는 캐시 파일 쓰기 때문에 실행 전 백업 권장.
