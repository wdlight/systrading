## 1. H0STCNI0 스펙 대응 정리

- **공식 필드 구조**: `docs/KIS-API/KIS-ws-H0STCNI0.spec.md` (21개 필드, `symbol` ~ `seq`) 기준으로 재정렬했다.
- **실제 샘플**: `005930^093000^62200^100^2^200^0.32^62200^62100^300^200^1^50000^48000^1.12^1200000^74500000000^62000^62500^61800^109`
- **핵심 매핑**  
  | 인덱스 | 필드 | 설명 | 코드 반영 |  
  | --- | --- | --- | --- |  
  | 0 | `symbol` | 종목 | `stock_code` |  
  | 1 | `tr_time` | 체결시간 HHMMSS | `executed_time` |  
  | 2 | `stck_prpr` | 현재가 | `price` |  
  | 3 | `stck_cntg_vol` | 체결 수량 | `trade_volume` |  
  | 15 | `vol` | 누적 거래량 | `acc_volume` |  
  | 16 | `value` | 누적 거래대금 | `acc_value` |  
  | 나머지 | `askp`, `bidp`, … | 보조 분석 용 | 동일 순번 적용 |

### 1.1 파서 업데이트 (`backend/app/domestic_websocket.py`)

```python
def receive_realtime_tick_domestic(raw: str) -> dict:
    values = raw.split("^")
    # _int/_float 헬퍼로 21개 필드 변환
    return {
        "stock_code": values[0],
        "executed_time": values[1],
        "price": _int(2),
        "trade_volume": _int(3),
        "change_sign": values[4],
        "change": _int(5),
        "change_rate": _float(6),
        "ask_price": _int(7),
        "bid_price": _int(8),
        "ask_qty": _int(9),
        "bid_qty": _int(10),
        "market_code": values[11],
        "total_ask_qty": _int(12),
        "total_bid_qty": _int(13),
        "volume_ratio": _float(14),
        "acc_volume": _int(15),
        "acc_value": _int(16),
        "open_price": _int(17),
        "high_price": _int(18),
        "low_price": _int(19),
        "sequence": _int(20),
        "raw_payload": raw,
    }
```

- 큐에 넣는 키도 한글 → 영문으로 정규화 (`stock_code`, `raw_payload`).
- `trade_volume`가 0일 때 `acc_volume` 증분으로 보정.

## 2. RealtimeDataService 확장 요약

### 2.1 상태 및 로그 설정
- `MinuteCandleState` 클래스 (`backend/app/models/realtime_minute.py`) 도입.

  ```python
  self.minute_state_lock = asyncio.Lock()
  ```

- 샘플 로그 (`logs/minute_candle_samples.log`)는 loguru 핸들로 초기 50건만 기록하고 이후 자동 비활성화.

### 2.2 체결 틱 처리 (`_handle_tick_data`)
1. 체결가 / 체결량 / HHMMSS → `parse_kis_time` 사용.
2. 누적 거래량 기반 체결량 보정 및 음수 보정.
3. 새 분봉 시작 시 `_flush_closed_candle`, `minute_candle_update` 브로드캐스트.
4. 워치리스트 가격 갱신은 기존 로직 유지.

### 2.3 분봉 확정 및 persistence 큐
```python
async def _flush_closed_candle(...):
```

- `_minute_state_cleanup_loop`는 10분 이상 미업데이트 상태를 제거.

## 4. 남은 연결 작업 (상세 가이드)

> “추가 참고 사항 1번” – 분봉 persistence와 REST 캐시 동기화

### 4.1 콜백 구현
1. 새 파일 `backend/app/services/realtime_persistence.py` (예시)
   ```python
   from datetime import datetime
   from app.services.trading_service import TradingService
   from app.models.schemas import ChartCandle

   async def persist_minute_candle(service: TradingService, stock_code: str, candle: ChartCandle) -> None:
       target_date = datetime.fromisoformat(candle.timestamp).replace(hour=0, minute=0, second=0, microsecond=0)
       success = await service.update_minute_candle(stock_code=stock_code, target_date=target_date, candle_data=candle)
       if not success:
           logger.warning(f"분봉 persistence 실패: {stock_code}, {candle.timestamp}")
   ```

### 4.2 FastAPI 초기화에서 주입
```python
trading_service = TradingService(korea_invest_service)
realtime_service.set_minute_persist_handler(
    lambda code, candle: persist_minute_candle(trading_service, code, candle)
)
app.state.trading_service = trading_service
```

### 4.3 검증 포인트
- 분 경계 전후로 `/api/chart/{code}/minute` 호출 → 실시간 finalize 반영 여부 확인.
- persistence 실패 시 재시도/경고 로그가 남는지 모니터링.

## 6. 후속 개선 아이디어

1. **재시도 로직**: persistence 실패 시 backoff 후 재삽입.
2. **finalize 메시지 활용**: 프런트에서 새 분봉 시작 시 REST 폴링을 유연하게 제어.
3. **다중 심볼 최적화**: 대량 종목 구독 시 상태 메모리를 줄이기 위한 LRU 전략 고려.
4. **테스트 자동화**: 모의 데이터로 분 경계 전후 시나리오를 replay하는 스크립트 추가.
