@doc/plan/mincandle/ 폴더의 내용과 실제 구현된 코드를 검토하고, 문제가 없는지 확인해 줘.

다음 사항에 대해서 답변을 해 줘.

1. 현재 websocket에서 data를 분봉 cache file에 업데이트를 하는 지 안하는 지 확인해 줘.
    
2. front에서 특정종목-삼성전자 의 호가를 보고 있다가. 하이닉스로 변경을 했어.  
    약 5분 정도 지난 후에 다시 삼성전자의 호가를 보려고 종목을 변경하였을 때에,  
    분봉의 지난 5분의 data와 실시간 data를 어떻게 받아오는 지 설명해 줘.
    

이외에 더 개선할 점에 대해서 검토해 줘.

**분봉 캐시 현황**

- 실시간 서비스는 분봉 완료 시 큐에 넣지만 _minute_persist_handler가 None으로 초기화된 상태라(backend/app/services/realtime_service.py:62-63) 퍼시스턴스 워커에서도 캐시 파일을 갱신하지 않고 로그만 남깁니다(backend/app/services/realtime_service.py:541-556).
- FastAPI 기동 시에도 핸들러를 주입하지 않아(backend/app/main.py:125-144) 계획서에서 언급한 TradingService.update_minute_candle 연동이 빠져 있습니다(docs/plan/mincandle/1018.impl.daily.plan.md:123-134).
- 현재 캐시 파일은 REST 엔드포인트가 호출될 때만 갱신됩니다. /api/chart/{stock_code}/minute/current가 최신 캔들을 받아온 뒤 update_minute_candle을 호출하여 JSON 캐시를 저장합니다(backend/app/api/chart.py:262-287, backend/app/services/trading_service.py:480-517).

**5분 공백 보충 흐름**

- 사용자가 5분 뒤 삼성전자로 돌아오면 useRealChartData가 즉시 재호출되어 /api/chart/005930/minute/full을 불러옵니다(stock-trading-ui/src/hooks/useRealChartData.ts:68-247).
- 백엔드 TradingService.get_full_day_candles는 저장된 캐시를 읽고, 최신 시각과 현재 시각 간 격차를 체크합니다(backend/app/services/trading_service.py:254-441). Gap(2분 이상)이 감지되면 ChartCacheService._fill_gap이 누락 구간만 KIS API에서 다시 받아 병합·저장합니다(backend/app/services/chart_cache_service.py:200-359). 이렇게 해서 빠져 있던 5분 분봉이 캐시에 채워집니다.
- 그다음 프런트는 새로 받은 chartData를 기반으로 렌더링하고(stock-trading-ui/src/components/trading/RealtimeCandlestickChart.tsx:41-67), useRealtimeMinuteCandles가 WebSocket에서 오는 minute_candle_update 스트림을 실시간으로 합칩니다(stock-trading-ui/src/hooks/useRealtimeMinuteCandles.ts:6-40). 서버 쪽에서는 _handle_tick_data가 틱을 분봉 상태로 누적하고 브로드캐스트 중입니다(backend/app/services/realtime_service.py:423-520).

**개선 제안**

- 앱 시작 시 TradingService.update_minute_candle을 직접 호출하는 persistence 핸들러를 주입하여, WebSocket만으로도 분봉 캐시가 최신 상태를 유지하도록 계획대로 마무리하는 것이 좋겠습니다(backend/app/services/realtime_service.py:585-587).
- 백엔드가 송신하는 minute_candle_finalize 이벤트를 프런트에서 활용하면, REST 호출 없이도 완료된 분봉을 차트 데이터에 반영할 수 있습니다(stock-trading-ui/src/lib/websocket.ts:539-544).

다음 단계 제안:

1. RealtimeDataService 초기화 코드에서 set_minute_persist_handler를 호출해 캐시 자동 갱신을 완성합니다.
2. 프런트 차트 훅에 MinuteCandleFinalizeMessage 처리를 추가하여 완성 분봉을 즉시 리스트에 반영하는지 검증해 보세요.

## Current New Minute candle Rendering Routine

다음의 시나리오에 대해서 답변을 해 줘.

1. 처음 삼성전자를 선택했어. > 화면에 분봉이 API로 부터 나온 값으로 chart rendering을 진행. > websocket에 구독된 H0STCNT0 의 값으로 front에 전달하여 실시간 minute candle update
2. 1분이 지난 후, 새로운 분봉의 첫 data는 어디서 어떻게 받아와서 candle을 rendering 하는가?

**초기 선택 → 실시간 업데이트**

- 삼성전자를 처음 선택하면 useRealChartData가 /api/chart/005930/minute/full을 호출해 캐시에 쌓인 분봉 데이터를 받아옵니다. 이 API는 TradingService.get_full_day_candles가 ChartCacheService를 통해 JSON 캐시를 읽고, 필요하면 KIS REST로 누락 구간을 보충한 뒤 반환하므로 화면은 곧바로 완성된 분봉 목록을 그립니다.
- 동시에 WebSocket(H0STCNI0 체결 채널)에 이미 연결돼 있으므로, 백엔드 RealtimeDataService._handle_tick_data가 체결 틱을 1분 단위로 집계해 minute_candle_update 메시지를 쏴 줍니다. 프런트의 useRealtimeMinuteCandles가 해당 종목 코드만 걸러서 마지막 캔들을 실시간 값으로 교체하거나 새 항목을 추가합니다.

**새 분봉이 시작될 때 첫 데이터 흐름**

- 1분이 지나 첫 틱이 들어오면 백엔드가 이전 상태의 minute_key와 비교해 분 경계를 감지하고, 우선 _flush_closed_candle로 직전 분을 확정해 minute_candle_finalize 브로드캐스트와 캐시 큐 적재를 수행합니다.
- 이어 같은 틱으로 새 MinuteCandleState를 생성합니다(시가·고가·저가·종가가 모두 첫 틱 가격, 체결량이 초깃값). 곧바로 같은 _handle_tick_data 루틴이 minute_candle_update 메시지를 내보내고, 프런트는 이를 받아 방금 시작한 분봉을 최초 데이터로 렌더링합니다.
- 이후 같은 분에 들어오는 추가 틱들은 동일 state에 누적되어 WebSocket 업데이트로 계속 반영됩니다. REST 쪽 캐시는 이후 /api/chart/.../minute/full 재호출 시 또는 persistence 핸들러가 연동되면 자동으로 최신화됩니다.

이 흐름 덕분에 새 분봉의 첫 캔들도 체결 틱이 도착하는 즉시 WebSocket을 통해 화면에 나타납니다.
