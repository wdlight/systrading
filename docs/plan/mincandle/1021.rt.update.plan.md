# /trview 실시간 분봉 업데이트 개선 계획

**문서 ID**: `1021.rt.update.plan`  
**작성일**: 2025-10-21  
**작성자**: Codex (GPT-5)  
**상태**: 초안

---

## 1. 코드 리뷰 결과 요약

- `useTRViewChart` 훅은 분봉/일봉 데이터를 REST API로만 로드하며 WebSocket 실시간 캔들 스트림을 전혀 통합하지 않고 있다 (`stock-trading-ui/src/hooks/useTRViewChart.ts:60-117`).  
- `/trview` 페이지는 위 훅이 만든 정적 `minuteChartData`를 그대로 `TRViewChart`에 전달하고 있으며, 실시간 캔들을 주입할 수 있는 `onReady` 콜백도 사용하지 않는다 (`stock-trading-ui/src/app/trview/page.tsx:152-185`).  
- `TRViewChart` 컴포넌트 자체는 `onReady`를 통해 `updateCandle` API를 노출하지만, 현재 호출자가 없으므로 WebSocket에서 들어온 데이터를 차트에 반영할 경로가 없다 (`stock-trading-ui/src/components/trading/TRViewChart.tsx:29-168`).  
- 실시간 분봉 스트림을 처리하는 `useRealtimeMinuteCandles` 훅과 `RealtimeCandlestickChart` 컴포넌트는 이미 구현되어 있으나 `/trview` 페이지에서는 사용되지 않는다 (`stock-trading-ui/src/components/trading/RealtimeCandlestickChart.tsx:41-116`).  
- 결과적으로 `/trview`의 분봉 차트는 초기 로딩 이후 갱신될 수단이 없어 1분 경계가 지나도 화면이 정지된 것처럼 보인다.

---

## 2. 문제 원인 정리

1. **데이터 소스 한정**: `/trview` 화면은 REST 기반 초기 분봉 배열만 활용하고 실시간 WebSocket 데이터를 병합하지 않는다.  
2. **차트 API 미사용**: 차트가 제공하는 `updateCandle` 진입점을 호출하지 않아 실시간 변화를 반영할 수 없다.  
3. **중복 구현**: 이미 마련된 실시간 분봉 훅과 컴포넌트를 재사용하지 않고 별도 경로를 쓰면서 유지보수 복잡도가 증가했다.

---

## 3. 개선 목표

- `/trview` 분봉 차트를 1초 이내 주기로 최신 캔들을 표시하도록 한다.  
- 기존 REST 기반 초기 로딩 흐름을 유지하면서 실시간 스트림을 자연스럽게 병합한다.  
- 재사용 가능한 훅/컴포넌트를 활용해 중복 코드를 최소화하고 테스트 부담을 줄인다.

---

## 4. 개선 단계

### 4.1 단계 1: 실시간 훅 통합 (우선)
1. `useTRViewChart` 내부에서 `useRealtimeMinuteCandles`를 조건부 호출(분봉 + enabled=true일 때)하고, 반환되는 `currentCandle`/`finalizedCandles`를 REST 데이터와 병합하는 `mergeRealtimeCandles` 유틸을 추가한다.  
2. 병합 결과를 `chartData` 대신 `enhancedChartData`로 노출하거나, 분봉 타임프레임일 때만 교체하여 기존 컴포넌트 호출부 변경을 최소화한다.  
3. 종목 전환 시 실시간 상태 초기화, 중복 타임스탬프 제거, 배열 크기 제한(예: 600분 = 10시간) 등 메모리 관리 로직을 함께 도입한다.

### 4.2 단계 2: 차트 업데이트 경로 연결
1. `/trview` 페이지에서 `TRViewChart`의 `onReady`를 활용해 `updateCandle` 핸들을 보관한다.  
2. `useTRViewChart`가 노출하는 실시간 캔들(특히 `currentCandle`) 변경을 감지해 `updateCandle`을 호출하고, 병합된 분봉 배열도 동기화해 초기 렌더링과 히스토리 이동이 일관되도록 한다.  
3. WebSocket 재연결/종목 전환 시 `updateCandle` 호출 순서를 보장하기 위해 최신 분 경계만 업데이트하도록 타임스탬프 필터를 둔다.

### 4.3 단계 3: 재사용 컴포넌트 전환 검토 (선택)
- `RealtimeCandlestickChart`가 이미 실시간 병합 로직을 포함하고 있으므로, UI 요구사항이 허용된다면 `/trview`에서 해당 컴포넌트로 교체하는 방안도 검토한다.  
- 교체 시 `TRViewChart`가 제공하던 TradingView 스타일 옵션(범례, onLoadPrevious 등)을 보완하거나, 필요한 기능만 `RealtimeCandlestickChart`에 이식한다.

## 5. 테스트 및 검증 계획

1. **기능 테스트**  
   - 동일 종목으로 2분 이상 관찰하며 분 경계마다 새 캔들이 생성되는지 확인.  
   - 종목을 변경했다 돌아올 때 직전 실시간 구간이 누락되지 않았는지 확인.  
   - WebSocket 강제 재연결(브라우저 DevTools에서 네트워크 offline/online) 후에도 업데이트가 이어지는지 확인.

2. **회귀 테스트**  
   - 일봉 차트 및 과거 데이터 로딩(스크롤/확대) 동작이 기존과 동일하게 유지되는지 검증.  
   - `OrderForm` 내 `OrderBook` 컴포넌트가 기존 방식대로 동작하는지 확인(호가 스트림과 충돌 여부 점검).

3. **로그/모니터링**  
   - `useRealtimeMinuteCandles`에서 분봉 finalize 이벤트 수신 시점과 `updateCandle` 호출 시점을 로그로 남겨 지연/중복을 확인.  
   - 필요 시 `minute_candle_update` 타임스탬프 역전 사례를 경고 로그로 포착한다.

## 6. 예상 작업량 및 리스크

- **작업량**: 1.5~2.5시간 (훅 병합 1시간 + 차트 이벤트 연동 0.5시간 + 수동 테스트 0.5~1시간).  
- **주요 리스크**:  
  - WebSocket 재연결 타이밍에서 중복 캔들이 삽입될 가능성 → 타임스탬프 기반 덮어쓰기 로직으로 완화.  
  - 차트 스크롤/확대 상태가 실시간 업데이트 때 초기화되는 현상 → `updateCandle` 사용으로 최소화.
