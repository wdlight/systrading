# Portfolio Backend 테스트 계획 (2025-10-11)

## 1. 목표

포트폴리오 이력 API 관련 백엔드 변경 사항(캐시 도입, 스냅샷/거래 재생, 잔고 파싱 개선 등)이 기존 기능과 안정적으로 동작하는지 검증한다. 특히 Redis 캐시, SnapshotManager, KoreaInvestAPI 서비스 변경이 서로 충돌 없이 연동되는지 확인한다.

## 2. 테스트 범위
- REST API: `GET /api/portfolio/history`
- 내부 서비스: `PortfolioAnalyticsService`, `BenchmarkService`, `TradeHistoryService`, `SnapshotManager`, `CashFlowTracker`
- KoreaInvest 연동: `KoreaInvestAPIService.get_account_balance`, `get_trade_history`, `get_index_chart_data`
- 캐시 계층: `CacheService` + Redis
- 스케줄러: `app.scheduler.portfolio_snapshot.save_portfolio_snapshot`
- 레거시 호환: `brokers.korea_investment.ki_api.get_acct_balance_tuple`

## 3. 테스트 환경 준비
1. **가상환경**: `cd backend && source vkis/bin/activate`
2. **환경 변수**: `.env` 최신화 및 Redis 접속 정보 확인 (`REDIS_URL`)
3. **Redis**: 로컬 Redis 인스턴스 실행 확인 (`redis-cli ping`)
4. **의존성 설치**: `pip install -r requirements.txt`
5. **테스트 데이터**: `data/snapshots/` 디렉터리 클린업(필요 시), Redis 캐시 FLUSH (테스트 격리 목적)

## 4. 테스트 시나리오

### 4.1 단위 테스트 (pytest)
- `pytest backend/tests/test_portfolio_analytics.py`
  - Mock된 KoreaInvest 서비스로 거래 재생, 캐시, 벤치마크 폴백 시나리오 검증
- `pytest backend/tests/test_trading_calendar_range.py`
  - 거래일 계산 로직 회귀 테스트
- `pytest backend/tests/test_simple_server.py`
  - `get_acct_balance_tuple` 반환 값 구조 확인

### 4.2 통합 테스트
- 스크립트: `python backend/scripts/test_portfolio_history.py`
  - 실제(또는 sandbox) KoreaInvest API를 호출하여 포트폴리오 이력을 수집
  - 캐시 Hit/Miss 로그 확인
- FastAPI 서버 구동 후 수동 호출
  - `uvicorn app.main:app --reload`
  - `curl -X GET "http://localhost:8000/api/portfolio/history?period=1W"`
  - 응답 필드(`date`, `portfolio`, `benchmark`) 및 TTL 동작 확인

### 4.3 캐시 검증
1. Redis 초기 상태 확인 (`redis-cli --scan | grep portfolio_history`)
2. API 첫 호출 → 캐시 미스 → `portfolio_history:1W` 생성 여부 확인
3. 두 번째 호출 → 캐시 히트 확인 (`CacheService` 로그, 응답 시간)
4. TTL 만료 후 재호출 → 미스 재발생 확인

### 4.4 Snapshot 스케줄러 검증
1. `python -m app.scheduler.portfolio_snapshot` (또는 별도 async runner)
2. `data/snapshots/` 에 `snapshot_YYYYMMDD.json` 생성 여부 확인
3. 파일 내용 (`cash`, `positions`, `total_asset`) 확인

### 4.5 레거시 경로 회귀
- `core/order_processor.py`를 사용하는 수동 스크립트 (또는 단위 테스트)에서 `get_acct_balance_tuple` 호출 확인
- `backend/simple_server.py`의 debug endpoint 호출 (`python backend/simple_server.py` 실행 후 `curl http://localhost:8000/api/account/balance`)

## 5. 성공 기준
- 모든 pytest가 통과 (특히 새로 추가된 fix 영역)
- Redis 캐시 Hit/Miss 동작이 예상대로 로그에 기록되고 TTL 재생성 확인
- Snapshot 파일이 오류 없이 저장되고, 이후 `PortfolioAnalyticsService`가 스냅샷을 활용해 계산 시작일을 조정
- FastAPI 테스트 호출에서 HTTP 200 응답과 유효한 JSON 배열 (`date`, `portfolio`, `benchmark`)을 반환
- Legacy 호출부가 튜플 반환을 정상 처리 (에러 로그 없음)

## 6. 리스크 및 대응
- **실계좌 연동 실패**: sandbox 계정 또는 mock 데이터로 대체, 로그 수집 강화
- **Redis 비가용**: 캐시 grace 처리 확인 (CacheService가 None 반환 시 API가 정상 동작해야 함)
- **스냅샷 디렉터리 권한**: CI 환경에서는 `data/snapshots/` 생성 권한 확인 필요

- 필요 시 CI 파이프라인에 Redis service 추가 및 캐시 검증 스텝 통합
- 스냅샷/캐시 동작 지표 Prometheus 수집 항목 검토
