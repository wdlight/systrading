## 🔍 정확한 문제 분석

### H0STCNI0의 목적

**H0STCNI0** = "주문 접수/체결 통보" (Own Order Execution Notification)

- **용도**: 사용자 자신의 주문이 체결되었을 때 통보받기
- **언제 데이터가 오는가**: **사용자가 주문을 내고, 그 주문이 체결되었을 때만**
- **분봉 데이터와의 관계**: ❌ **직접적인 관계 없음!**

### ⚠️ 중요한 오해

**H0STCNI0는 실시간 분봉 데이터용이 아닙니다!**

분봉 데이터를 위해서는 다른 TR_ID가 필요합니다:

| TR_ID        | 용도               | 분봉 관련성          |
| ------------ | ---------------- | --------------- |
| **H0STCNI0** | 내 주문 체결 통보       | ❌ 분봉과 무관        |
| **H0STASP0** | 실시간 호가 (10단계)    | ⚠️ 간접적 (현재가 포함) |
| **H0STAS0**  | 실시간 시세           | ✅ **분봉에 필요!**   |
| **분봉 API**   | 주기 조회 (REST API) | ✅ **분봉 데이터**    |

## 🔬 H0STCNI0 데이터가 없는 이유

### 정상적인 동작입니다!

H0STCNI0는 다음 조건에서만 데이터가 옵니다:

1. ✅ WebSocket 연결 성공
2. ✅ H0STCNI0 구독 성공
3. ✅ AES KEY/IV 수신
4. ⚠️ **사용자가 주문을 내야 함**
5. ⚠️ **그 주문이 체결되어야 함**

**오늘 로그를 보면**: 주문을 내지 않았기 때문에 H0STCNI0 데이터가 없는 것이 정상입니다.

### 검증 방법:

```bash
# 실제 주문 체결 시 H0STCNI0 데이터가 와야 함
1. 주문 실행 (매수/매도)
2. 체결 발생
3. H0STCNI0 데이터 수신 확인
   → "[H0STCNI0] raw payload" 로그 확인
```
