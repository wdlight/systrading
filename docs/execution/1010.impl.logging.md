# 백엔드 로깅 시스템 개선 작업 보고서 (2025-10-10)

## 1. 작업 개요

- **작업 유형**: 시스템 리팩토링
- **작업 일시**: 2025년 10월 10일
- **담당자**: Gemini
- **관련 계획**: `docs/plan/1010.logging.plan.md`

## 2. 요약

백엔드 전체의 로깅 시스템을 `loguru` 기반의 중앙 설정 방식으로 개편했습니다. `backend/app/core/logging_config.py` 모듈을 신설하여 로깅 설정을 중앙화하고, `.env` 파일을 통해 로그 레벨 및 포맷(console/json)을 동적으로 제어할 수 있도록 구현했습니다. 또한, `uvicorn` 등 표준 라이브러리 로그를 모두 `loguru`가 처리하도록 통합하여 로그 포맷의 일관성을 확보하고, 파일 로테이션 및 보존 정책을 적용하여 운영 안정성을 높였습니다.

---

## 3. 상세 작업 내역

본 작업은 `1010.logging.plan.md`에 정의된 5단계에 따라 진행되었습니다.

### Phase 1: 환경 설정 및 의존성 추가

- **`backend/requirements.txt`**: `loguru` 의존성이 이미 포함되어 있음을 확인했습니다.
- **`backend/.env.example`**: 로깅 설션을 `LOG_LEVEL=INFO`와 `LOG_FORMAT=console`로 수정하여 템플릿을 업데이트했습니다.
- **`backend/.env`**: 실제 운영에 사용될 `.env` 파일을 신규 생성하고, 위와 동일한 로깅 설정을 추가했습니다.
- **`backend/app/core/config.py`**: `Settings` 클래스에 `LOG_LEVEL`과 `LOG_FORMAT` 필드를 추가하여, 애플리케이션이 환경 변수를 인식할 수 있도록 수정했습니다.

### Phase 2: 중앙 로깅 설정 모듈 구현

- **`backend/app/core/logging_config.py`**: 신규 파일을 생성하여 `setup_logging` 함수를 구현했습니다. 이 함수는 다음 기능을 포함합니다.
    - `.env`의 설정 값을 읽어 동적으로 로거를 설정합니다.
    - 콘솔(stdout) 핸들러와 일별 로그 로테이션이 적용된 파일 핸들러를 추가합니다.
    - `LOG_FORMAT` 값에 따라 파일 로그를 `json` 또는 `text` 형식으로 자동 전환합니다.
    - `InterceptHandler`를 구현하여 `stdlib logging`으로 생성되는 모든 로그(e.g., `uvicorn`)를 `loguru`가 가로채도록 설정했습니다.
- **`utils/logger.py`**: 기능이 `logging_config.py`로 완전히 이전되어 불필요해졌으며, 삭제 대상으로 분류되었습니다.

### Phase 3: FastAPI 앱에 로거 적용 및 초기화

- **`backend/app/main.py`**:
    - 애플리케이션 시작 시점에 `setup_logging()`을 호출하도록 수정했습니다.
    - 기존의 `logging.basicConfig()` 및 `try-except` 기반의 fallback 로거 설정을 모두 제거했습니다.
    - 디버깅 목적의 `print()` 구문을 `logger.debug()`로 변경했습니다.
- **`backend/app/core/korea_invest.py`**:
    - 불필요한 `logging.basicConfig()` fallback 로거 설정을 제거했습니다.

### Phase 4: 백엔드 전체 모듈의 로거 교체

- 백엔드 전체의 일관성을 위해 `from loguru import logger`를 사용하도록 표준화했습니다.
- 아래 모듈들에서 `import logging` 및 `logging.getLogger()` 구문을 `loguru`로 교체했습니다.
    - **`backend/app/api/`**: `account.py`, `trading.py`, `watchlist.py`, `websocket.py`
    - **`backend/app/services/`**: `account_service.py`, `trading_service.py`, `technical_analysis_service.py`, `watchlist_service.py`
    - **`backend/app/websocket/`**: `connection.py`
- `chart.py`, `stocks.py`, `chart_cache_service.py`, `realtime_service.py`, `stock_info_service.py`, `stock_service.py`는 이미 `loguru`를 사용하고 있어 수정이 불필요했습니다.

### Phase 5: 검증 및 문서화

- **`docs/execution/impl20250911_logging.md`**: 해당 문서가 더 이상 유효하지 않음을 알리는 아카이브 문구를 상단에 추가했습니다.
- **멀티프로세스 테스트**: `backend/vkis/bin/python` 환경에서 `from app import main` 시도 시 `PermissionError: [Errno 13]`가 발생하여, 원인을 `loguru`의 `enqueue=True` 설정으로 규정하고 재현 로그를 확보했습니다.

## 4. 보완 작업 (2025-10-10 오후)

초기 적용 후 다음 문제가 확인되어 추가 수정이 진행되었습니다.

1. **파일 핸들러 큐 사용 시 권한 오류**
   - 증상: `enqueue=True`로 설정한 `logger.add()`에서 `SemLock` 생성 권한이 없어 `PermissionError`가 발생함 (`backend/app/core/logging_config.py`).
   - 조치: `.env`/`Settings`에 `LOG_ENQUEUE` 옵션을 신설하고 기본값을 `false`로 설정하여 큐 사용 여부를 환경 변수로 제어. 권한이 보장된 환경에서만 활성화할 수 있도록 함.

2. **Uvicorn 기본 로깅 재설정 문제**
   - 증상: `uvicorn.run()`이 내부 `logging.config.dictConfig`를 재적용하면서 `InterceptHandler`가 무시됨.
   - 조치: `uvicorn.run(..., log_config=None, log_level=settings.LOG_LEVEL.lower())`로 호출하여 uvicorn이 추가 설정을 덮어쓰지 않도록 변경.

3. **웹소켓 워커 로그 분리 문제**
   - 증상: `domestic_websocket` 하위 프로세스에서 중앙 설정이 적용되지 않아 별도 포맷의 로그가 출력됨.
   - 조치: 워커 모듈 진입 시 `setup_logging()`을 재호출해 메인 프로세스와 동일한 sink/포맷을 사용하도록 수정.

위 조치 이후 `backend/vkis/bin/python - <<'PY' ... from app import main` 실행이 오류 없이 통과함을 확인했습니다.

## 4. 결과

- **중앙 관리**: 모든 로깅 정책은 `backend/app/core/logging_config.py`에서 관리됩니다.
- **동적 설정**: `.env` 파일을 통해 코드 수정 없이 로그 레벨과 포맷(console/json) 변경이 가능합니다.
- **안정적인 로그 저장**: 매일 자정, 로그 파일이 자동으로 분리되어 저장되며(`logs/backend_app_YYYY-MM-DD.log`), 30일치 로그가 보관됩니다.
- **통합된 로그 포맷**: FastAPI, Uvicorn, 소켓 워커 등 백엔드에서 발생하는 모든 로그가 `loguru`의 일관된 포맷으로 출력 및 저장됩니다.
