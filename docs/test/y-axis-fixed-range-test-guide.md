# Y축 고정 범위 기능 테스트 가이드

**작성일**: 2025-10-02
**대상**: Frontend 차트 Y축 고정 기능
**테스트 환경**: http://localhost:9000/test-chart

---

## 🎯 테스트 목적

시초가 기준 ±30% 범위로 Y축을 고정하는 기능이 정상 작동하는지 검증

---

## 📋 구현 내용

### 주요 기능
1. **시초가 기준 고정**: 첫 캔들의 open 가격 기준 ±30% 범위
2. **호가 단위 정렬**: Y축 범위를 호가 단위에 맞춰 깔끔하게 표시
3. **실제 범위 검증**: 극단적 가격 변동 시 자동 범위 확장
4. **Drag 불변성**: 차트를 drag해도 Y축 범위 유지

### 적용된 개선사항
- ✅ Option 1: 호가 단위 반영
- ✅ Option 2: 실제 가격 범위 검증
- ⏸️ Option 3: 전날 종가 기준 (Backend 지원 필요)

---

## 🧪 테스트 시나리오

### 시나리오 1: 기본 Y축 고정 확인

**목적**: 시초가 기준 ±30% 범위가 올바르게 계산되는지 확인

**테스트 단계**:
1. http://localhost:9000/test-chart 접속
2. 삼성전자(005930) 1분봉 차트 로드
3. 브라우저 Console 열기 (F12)
4. Console에서 Y축 범위 로그 확인

**예상 결과**:
```javascript
📊 Y축 고정 (시초가 기준 ±30%, 호가 단위 정렬): {
  openingPrice: 60000,
  tickUnit: 50,
  baseRange: "42,000 ~ 78,000",
  actualRange: "59,500 ~ 60,500",
  finalRange: "42,000 ~ 78,000",
  expanded: false
}
```

**검증 항목**:
- [ ] `openingPrice`가 시초가와 일치
- [ ] `baseRange`가 시초가 × 0.70 ~ 1.30
- [ ] `tickUnit`이 가격대에 맞는 호가 단위
- [ ] Y축 범위가 호가 단위로 정렬됨

---

### 시나리오 2: Drag 시 Y축 불변 확인

**목적**: 차트를 drag해도 Y축이 고정되어 있는지 확인

**테스트 단계**:
1. 차트를 좌측으로 drag (과거 데이터 조회)
2. Console에서 Y축 범위 로그 확인
3. 차트를 우측으로 drag (최신 데이터 조회)
4. Console에서 Y축 범위 로그 확인

**예상 결과**:
- Drag 전후 Y축 범위 동일 유지
- `finalRange`가 변경되지 않음

**검증 항목**:
- [ ] 좌측 drag 시 Y축 불변
- [ ] 우측 drag 시 Y축 불변
- [ ] 캔들의 상대적 크기 일정 유지
- [ ] 가격 스케일 일관성 유지

---

### 시나리오 3: 호가 단위 정렬 확인

**목적**: Y축 범위가 호가 단위에 맞춰 깔끔하게 정렬되는지 확인

**테스트 단계**:
1. 차트 Y축 눈금(tick) 확인
2. Console에서 `tickUnit` 값 확인
3. Y축 최소/최대값이 tickUnit의 배수인지 확인

**예상 결과**:
```javascript
// 시초가 60,000원 → tickUnit = 50원
lowerLimit: 42,000 = Math.floor(42,000 / 50) * 50
upperLimit: 78,000 = Math.ceil(78,000 / 50) * 50
```

**호가 단위 기준표**:
| 가격 범위 | 호가 단위 |
|----------|----------|
| 2,000원 미만 | 1원 |
| 2,000 ~ 5,000원 | 5원 |
| 5,000 ~ 20,000원 | 10원 |
| 20,000 ~ 50,000원 | 50원 |
| 50,000 ~ 200,000원 | 100원 |
| 200,000 ~ 500,000원 | 500원 |
| 500,000원 이상 | 1,000원 |

**검증 항목**:
- [ ] Y축 최소값이 tickUnit의 배수
- [ ] Y축 최대값이 tickUnit의 배수
- [ ] Y축 눈금이 깔끔하게 표시됨

---

### 시나리오 4: 실제 범위 검증 (자동 확장)

**목적**: 가격이 ±30% 범위를 벗어날 경우 자동 확장되는지 확인

**테스트 단계**:
1. 급등/급락 종목으로 변경 (예: 테마주)
2. Console에서 `expanded: true` 확인
3. `actualRange`와 `finalRange` 비교

**예상 결과** (가격이 ±30% 벗어난 경우):
```javascript
📊 Y축 고정 (시초가 기준 ±30%, 호가 단위 정렬): {
  openingPrice: 10000,
  tickUnit: 10,
  baseRange: "7,000 ~ 13,000",
  actualRange: "6,500 ~ 13,500",  // 범위 벗어남
  finalRange: "6,500 ~ 13,500",   // 자동 확장
  expanded: true                   // 확장 발생
}
```

**검증 항목**:
- [ ] `expanded: true` 표시
- [ ] `finalRange`가 `actualRange` 포함
- [ ] 모든 캔들이 Y축 범위 내 표시
- [ ] 데이터 손실 없음

---

### 시나리오 5: 다양한 종목 테스트

**목적**: 다양한 가격대의 종목에서 정상 작동하는지 확인

**테스트 대상**:
| 종목 | 코드 | 가격대 | 호가 단위 | 예상 Y축 범위 |
|------|------|--------|----------|--------------|
| 삼성전자 | 005930 | 60,000원 | 50원 | 42,000 ~ 78,000 |
| POSCO | 005490 | 300,000원 | 500원 | 210,000 ~ 390,000 |
| 저가주 | - | 1,000원 | 1원 | 700 ~ 1,300 |
| 고가주 | - | 600,000원 | 1,000원 | 420,000 ~ 780,000 |

**테스트 단계**:
1. 각 종목별로 차트 로드
2. Console에서 Y축 범위 확인
3. 호가 단위 적용 여부 확인

**검증 항목**:
- [ ] 저가주 (1원 단위) 정상 작동
- [ ] 중가주 (50원 단위) 정상 작동
- [ ] 고가주 (1,000원 단위) 정상 작동
- [ ] 모든 가격대에서 ±30% 범위 유지

## 🐛 알려진 이슈 및 대응

### Issue 1: 시초가 데이터 누락
**증상**: 첫 캔들이 시초가가 아닌 경우
**원인**: Backend 데이터 정렬 오류 또는 시간외 거래 포함
**대응**: Backend chart.py에서 정규장(9:00~) 데이터만 반환 확인

### Issue 2: TypeScript 타입 오류
**증상**: `ActiveDotType` 타입 경고 (Line 485)
**원인**: Recharts 라이브러리 타입 정의 불일치
**대응**: 기능상 문제 없음, 향후 타입 수정 예정

### Issue 3: 극단적 변동 시 범위 과다 확장
**증상**: 상한가/하한가 도달 시 Y축 범위가 너무 넓어짐
**원인**: 실제 범위 검증 로직이 과도하게 확장
**대응**: 확장 제한 로직 추가 고려 (최대 ±40% 제한 등)
