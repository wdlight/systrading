### 이슈 #1: `minute_candle_update` 메시지 스키마 불일치

**지적 내용**:

- 문서(v2.0.md:300)는 `"candle"` 필드와 `"is_final"` 값을 포함한다고 명시
- 실제 코드(realtime_service.py:568)는 `"data"` 필드만 사용하고 `is_final` 없음

**검증 결과**:

**문서 (v2.0.md:314-323)**:

```json
{
  "type": "minute_candle_update",
  "stock_code": "005930",
  "candle": {
    "timestamp": "2025-10-21T14:05:00",
    "open": 71500,
    "high": 71800,
    "low": 71400,
    "close": 71700,
    "volume": 0,
    "is_final": false  // ← 문서에 명시됨
  }
}
```

**실제 코드 (realtime_service.py:565-577)**:

```python
payload = {
    "type": "minute_candle_update",
    "stock_code": stock_code,
    "data": {  # ← "candle"이 아니라 "data"
        "timestamp": state.minute_key,
        "open": state.open,
        "high": state.high,
        "low": state.low,
        "close": state.close,
        "volume": state.volume,
        "last_tick": state.last_tick_ts.isoformat(),
        # ← "is_final" 없음
    }
}
```

**판단**: ✅ **지적 사항 수용**

- 문서와 코드가 명확히 불일치
- Frontend는 문서를 보고 `candle` 필드와 `is_final`을 기대할 것
- 실제 코드는 `data` 필드만 제공
- **수정 필요**: 코드를 문서에 맞춰 수정

### 이슈 #2: `minute_candle_finalize` 메시지 타입/구조 불일치

- 실제 코드(realtime_service.py:603)는 `"minute_candle_finalize"` 타입과 `"data"` 페이로드

**검증 결과**:

**문서 (v2.0.md:352-353)**:

```json
{
  "type": "minute_candle_finalized",  // ← "finalized" (과거분사)
  "stock_code": "005930",
  "candle": {  // ← "candle" 필드

  }

```

**실제 코드 (realtime_service.py:602-606)**:

```python

    "type": "minute_candle_finalize",  # ← "finalize" (동사원형)
```

**판단**: ✅ **지적 사항 수용**

- 타입 이름이 다름: `finalized` vs `finalize`
- 필드 이름이 다름: `candle` vs `data`
- Frontend 구독 로직에서 타입 매칭 실패 가능
- **수정 필요**: 코드를 문서에 맞춰 수정

**추가 고려사항**:

- `finalized` (과거분사)가 의미상 더 정확 ("완료된 분봉")

### 이슈 #3: 로그 패턴 불일치

**지적 내용**:

- 문서(v2.0.md:522)는 `[MINUTE-FINALIZED]` 같은 신규 로그 패턴 전제
- 실제 코드(realtime_service.py:568)는 `[H0STCNI0-BE]` 로그만 사용

**검증 결과**:

**문서에서 기대하는 로그 패턴**:

```bash
grep "HOGA-NEW-CANDLE|HOGA-UPDATE|HOGA-FLUSH|MINUTE-FINALIZED"
```

**실제 코드의 로그**:

```python
# _broadcast_minute_snapshot (Line 556)
logger.info("[H0STCNI0-BE] snapshot 준비 - ...")

# _flush_closed_candle (Line 591, 610)
logger.info("[H0STCNI0-BE] finalize 준비 - ...")
logger.info("[H0STCNI0-BE] finalize 완료 - ...")
```

**grep 결과**:

```bash
grep "MINUTE-FINALIZED" realtime_service.py
# → 0건 (존재하지 않음)
```

**판단**: ✅ **지적 사항 수용**

- 문서에 명시된 `[MINUTE-FINALIZED]` 로그가 코드에 없음
- 기존 `[H0STCNI0-BE]` 로그는 체결 데이터 관련 레거시 패턴
- 호가 기반 업데이트는 `[HOGA-XXX]` 패턴 사용 중 (일관성 있음)
- **수정 필요**:
  - `_flush_closed_candle`에 `[MINUTE-FINALIZED]` 로그 추가
  - `_broadcast_minute_snapshot`에 `[MINUTE-UPDATE]` 로그로 변경

### 이슈 #4: 지연된 체결 데이터로 인한 분봉 역전 문제

**지적 내용**:

- 호가가 먼저 새 분(14:06) 상태를 만들고
- 지연된 체결(14:05)이 도착하면
- 14:06 캔들이 빈 상태로 확정된 후 14:05 분봉이 재생성되는 역전 발생

**시나리오 분석**:

```
14:06:00.100  호가 71800원 도착 (minute_key = "14:06:00")
              → state 있음 (14:05 분봉)
              → state.minute_key != minute_key
              → _flush_closed_candle(14:05) 호출 ✅
              → 새 state 생성 (14:06, open=71800, volume=0)

14:06:00.500  체결 71750원, 100주 도착 (executed_time = "14:05:59")
              → minute_key = "14:05:00" (과거!)
              → state 있음 (14:06 분봉)
              → state.minute_key != minute_key
              → _flush_closed_candle(14:06) 호출 ⚠️ (문제!)
              → 14:06 분봉이 빈 상태로 완료됨
              → 새 state 생성 (14:05, open=71750, volume=100)
              → 시간 역전 발생!
```

**코드 검증 (realtime_service.py:515-517)**:

```python
if state and state.minute_key != minute_key:
    await self._flush_closed_candle(stock_code, state)
    state = None
```

**판단**: ✅ **지적 사항 수용** - 실제 문제 존재

**문제의 심각성**:

1. **데이터 무결성 문제**: 이미 완료된 14:05 분봉이 다시 생성됨
2. **순서 역전**: 14:06 분봉이 14:05 분봉보다 먼저 완료됨
3. **Frontend 혼란**: 차트가 깜빡이거나 잘못된 데이터 표시

**근본 원인**:

- 체결 데이터의 `executed_time`이 도착 시각보다 과거일 수 있음
- 네트워크 지연, 증권사 API 버퍼링 등으로 지연 도착 가능
- 현재 코드는 `minute_key`만 비교하여 과거 데이터 검증 없음

**수정 필요**:

1. **과거 데이터 검증**: 체결 데이터의 `minute_key`가 현재 `state.minute_key`보다 과거면 무시
2. **로그 경고**: 지연된 체결 데이터 감지 시 경고 로그
3. **가드 로직**: 분봉 역전 방지

**수정 예시**:

```python
if state and state.minute_key != minute_key:
    # 🔥 NEW: 과거 데이터 검증
    if minute_key < state.minute_key:
        logger.warning(
            f"⚠️ [DELAYED-TICK] {stock_code} 지연된 체결 데이터 무시 "
            f"(tick_minute={minute_key}, current_state={state.minute_key})"
        )
        return  # 과거 데이터는 무시

    # 정상적인 분 경계 (미래로 진행)
    await self._flush_closed_candle(stock_code, state)
    state = None
```

**요청 내용**:

- 장 시간에 구독 수신되는 H0STASP0 raw data 로깅 필요
- 쉽게 disable 가능해야 함

**제안 방안**:

1. **환경 변수 또는 설정 플래그 사용**
   
   ```python
   # __init__ or config
   self._enable_hoga_raw_log = os.getenv("ENABLE_HOGA_RAW_LOG", "false").lower() == "true"
   ```

2. **조건부 로깅**
   
   ```python
   if self._enable_hoga_raw_log:
       logger.debug(f"📥 [HOGA-RAW] {stock_code} | {hoga_data}")
   ```

3. **Disable 방법**:
   
   - 환경 변수: `ENABLE_HOGA_RAW_LOG=false`
   - 또는 코드에서 `self._enable_hoga_raw_log = False`
