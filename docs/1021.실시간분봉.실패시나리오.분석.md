### 3. Persistence Queue 오버플로우

**위치**: `backend/app/services/realtime_service.py:564-568`

**원인**:

```python
self.minute_finalize_queue: asyncio.Queue[Tuple[str, ChartCandle]] = asyncio.Queue(maxsize=200)

async def _enqueue_candle_for_persistence(self, stock_code: str, candle: ChartCandle) -> None:
    try:
        self.minute_finalize_queue.put_nowait((stock_code, candle))  # ⚠️ 큐가 가득 차면 실패
    except asyncio.QueueFull:
        logger.warning(f"minute_finalize_queue 가득 참: {stock_code}, {candle.timestamp}")
        # ⚠️ 데이터 손실! 재시도 없음
```

**발생 조건**:

- 200개 종목이 동시에 1분 경계를 통과
- Persistence worker가 느리게 처리 중
- 디스크 I/O 지연

**영향**:

- 완성된 분봉이 캐시 파일에 저장되지 않음
- `minute_candle_finalize` 이벤트는 브로드캐스트되지만 persistence는 실패
- 프론트엔드 새로고침 시 데이터 누락

**해결 방법**:

1. `maxsize` 증가 (200 → 1000)
2. 재시도 로직 추가
3. Dead-letter queue 구현

**우선순위**: 🔴 **P1 - 1주일 이내**

### 8. 동시 접근으로 인한 상태 손상 (minute_candle_state)

**위치**: `backend/app/services/realtime_service.py:492-512`

**문제**:

```python
async with self.minute_state_lock:  # ⚠️ Lock은 있지만...
    state = self.minute_candle_state.get(stock_code)

    if state and state.minute_key != minute_key:
        await self._flush_closed_candle(stock_code, state)  # ⚠️ Lock 내부에서 비동기 호출!
        state = None
```

**잠재적 Race Condition**:

1. Thread A: Lock 획득 → `_flush_closed_candle()` 호출 (비동기)
2. Thread B: `_flush_closed_candle()` 내부에서 `broadcast()` 호출
3. Thread C: Lock 대기 중이지만, B는 Lock 밖에서 실행 중
4. B와 C가 동시에 `minute_candle_state` 접근 가능

**증상**:

- 간헐적으로 분봉 데이터가 섞임
- 타임스탬프 순서 역전
- 중복 분봉 생성

**해결 방법**:

```python
async with self.minute_state_lock:
    state = self.minute_candle_state.get(stock_code)

    if state and state.minute_key != minute_key:
        # ✅ Lock 내부에서 동기적으로 처리
        candle_to_flush = state.to_chart_candle()
        self.minute_candle_state.pop(stock_code, None)

# ✅ Lock 외부에서 브로드캐스트
await self._flush_closed_candle(stock_code, candle_to_flush)
```

**우선순위**: 🔴 **P1 - 1주일 이내**

### 11. 체결량 0 또는 음수

**위치**: `backend/app/services/realtime_service.py:464-475`

**코드**:

```python
trade_volume = int(data.get("trade_volume", 0) or 0)
acc_volume = int(data.get("acc_volume", 0) or 0)

# Fallback: 누적 거래량 증분으로 체결량 계산
previous_acc = self._last_acc_volume.get(stock_code)

- 분봉의 `volume` 필드가 부정확
- 거래량 기반 지표 (VWAP 등) 오류

**해결 방법**:

1. 한국투자증권 API 문서 확인
2. `trade_volume=0`인 경우 이전 분봉 volume과 비교
3. 거래량 검증 로직 강화

**우선순위**: ⚠️ **P2 - 2주일 이내**

### 12. 분 경계 Race Condition

**위치**: `backend/app/services/realtime_service.py:495-497`

**시나리오**:

```

        minute_key=minute_key,  # 09:01

**영향**:

- 늦게 도착한 09:00 데이터가 09:01 분봉에 섞임

3. 프론트엔드에서 타임스탬프 검증
