### 1. React Hooks 순서 위반 (Critical)

**문제**:
```
React has detected a change in the order of Hooks called by OrderBook.
```

**원인**:
- `useCallback`, `useEffect` 등의 Hook이 조건부 리턴(`if` 문) 이후에 선언됨
- React는 Hook이 항상 같은 순서로 호출되어야 함

**해결** (`OrderBook.tsx`):
```typescript
// ❌ 이전: Hook이 조건문 이후
if (isLoading) return <Loading />;
const callback = useCallback(...); // 에러!

// ✅ 수정: 모든 Hook을 최상단에 선언
const callback = useCallback(...);
const value = useMemo(...);
useEffect(...);

// 이후 조건부 리턴
if (isLoading) return <Loading />;
```

### 2. 1초 Throttling으로 인한 업데이트 누락 (Critical)

**문제**:
- WebSocket에서 초당 여러 번 데이터를 받지만, 1초에 1번만 처리
- 대부분의 실시간 업데이트가 무시됨

**원인** (`useOrderBook.ts:202-206`):
```typescript
const unsubscribeWs = subscribeToOrderBookUpdates(stockCode, (update) => {
  const now = Date.now();
  if (now - lastUpdateRef.current < 1000) {
    return; // ❌ 1초 이내 업데이트 무시!
  }
  lastUpdateRef.current = now;
  setOrderBook(...);
});
```

**해결**:
```typescript
const unsubscribeWs = subscribeToOrderBookUpdates(stockCode, (update) => {
  lastUpdateRef.current = Date.now();

});
```

### 3. useMemo 의존성 배열 문제 (Major)

**문제**:
- `useMemo`가 `orderBook?.asks` 배열 참조를 의존성으로 사용
- 배열은 매번 새로운 참조이므로, 의존성이 항상 변경됨
- 또는 반대로 timestamp가 동일하면 재계산 안 됨

**원인** (`OrderBook.tsx`):
```typescript
const asks = useMemo(() => {
  return (orderBook?.asks ?? []).slice(0, 5).reverse();
}, [orderBook?.timestamp, orderBook?.asks]); // ❌ 배열 참조 문제
```

**해결**:
```typescript
// ✅ useMemo 완전 제거 - 5개 항목이라 성능 문제 없음
const asks = (orderBook.asks ?? []).filter(item => item.price > 0).slice(0, 5).reverse();
const bids = (orderBook.bids ?? []).filter(item => item.price > 0).slice(0, 5);
```

**수정 파일**: `src/components/trading/OrderBook.tsx`
**수정 위치**: Line 298-307

## 📌 주요 교훈

1. **React Hooks 규칙 준수 필수**
   - Hook은 항상 같은 순서로 호출되어야 함
   - 조건문보다 먼저 선언

2. **State 참조 동일성 중요**
   - React는 참조가 같으면 렌더링 안 함
   - 매번 새로운 객체 생성 필요 시 `_updateId` 같은 unique field 추가

3. **Throttling은 신중하게**
   - 실시간 데이터에서는 오히려 사용자 경험 저해
   - 성능 문제가 실제로 발생할 때만 적용

4. **useMemo/useCallback 남용 금지**
   - 작은 데이터 (5-10개)는 그냥 계산하는 게 더 빠름
   - 메모이제이션이 오히려 복잡도만 증가

5. **디버깅은 로그가 핵심**
   - 각 단계마다 명확한 로그 추가
   - 문제 발생 지점을 정확히 파악 가능
